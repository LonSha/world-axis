## Proposal

下一阶段保留两条线：优化提升解决时间、事务、容量、摘要与证据的约束；功能拓展完成 S1 离线恢复、S2 远方自动生命周期、S3 可确认的种子新局。按三个大版本推进，每版同时交付必要的优化和完整玩家路径。

收益按玩家实际行为评估：返回旧局能看到真实变化，正常游玩能收到按时抵达的远方消息，在空新局确认后能继承选定种子的结构。模块导出、文件存在与局部专锁通过分别记录，不替代上述行为。

### 优化提升线

| 编号 | 任务 | 拟交付物 | 验收条件 |
|---|---|---|---|
| SP1 | 时间来源与游玩生命周期 | 真实活动时间、剧情时间、测量时间的取用表；每聊天活动基准与恢复入口 | 剧情跳日不伪造真实离线，真实离开不暗改剧情钟；缺失或歧义的剧情时间明确拒算；刷新、切聊天、页面恢复不重复结算 |
| SP2 | 候选草稿结算与提交 | 从既有引擎提取的同草稿结算函数；公开事务入口复用这些函数；提交前聊天与状态校验 | 只修改所给草稿；整批失败无半写；切聊天和并发更新使旧候选失效；失败重试可复现 |
| SP3 | 摘要与注入生命周期 | 按已提交变化生成的批次摘要；摘要展示与注入共用内容；确认生成后的消费标记 | 无实际推进不报推进成功；受保护改动不写成已发生；生成取消或失败保留摘要，成功消费后普通后续轮次不反复注入旧摘要 |
| SP4 | 队列、预算与长局容量 | 分别声明推演上限、远方窗口预算、在途容量、转移包容量；接入现有容量与性能台账 | 预算削减保留未处理窗口；封路不吞在途消息；容量满有明确裁决；关闭功能无恢复或推进写入；大存档成本有实测记录 |
| SP5 | 审计证据与测试判据 | 输入依赖清单；真实接入点的正反验收；改动所涉门禁回填 | 间接读取面进入审计快照；过期证据不计健康；源码破坏能让同款行为判据失败；测试计数由现场汇总 |
| SP6 | 面板操作与真实宿主验收 | 从预览到确认、成功、失败的完整交互；三条玩家路径的宿主证据 | UI 操作能读到实际提交结果；桌面与手机布局可用；导入、切聊天、生成、重载的真实 SillyTavern 证据齐全 |

SP1 的前置事实必须先解决：`core/clock.js` 的 `now(site)` 当前默认返回墙钟、冻结后返回虚拟决策时间；它本身不证明剧情日期已推进。`farfield` 的参数按毫秒计算日窗口，不能把模块注释里的“世界钟”当作已有剧情日钟。实施时先核对 clock/calendar/chrono/日程与地区延迟的实际单位，再确定统一取值与存量时间迁移；未知时间保留未知状态，不猜日期。

SP2 的前置事实同样明确：`life.tick`、`evolution.tick` 自行调用 `store.transact`，`world.tick` 经 mutate 写入。它们不能直接作为 `offlineTick.tick` 的 apply 回调。需要提取可接收草稿的原有结算逻辑，避免另写一套推演规则。随机流、模块计数器、日志与其他外部副作用也在隔离核查面内；不得仅凭世界状态可回滚便承诺整批可复现。优先使用可复现的批次随机输入，提交后再发布成功副作用。

### 功能拓展线

- [ ] **S1 离线恢复编排**

  > 交付状态（v2.156.0）：`engines/offline-return.js` 已落地 —— 零 localStorage + 恰一处世界事务、票据分九码、摘要源名与注入链同名；`engines/playtime.js` 提供活动基准。**本条目仍不勾选**：下列验收场景中「切聊天 / 并发更新 / 第二轮抛错 / 重试」的端到端行为仅以专锁（31 / 39 / 19，收口轮另有 sp2 47 与 sp3 41）在无头环境做过，入口已有 before/after 与成功后聊天订阅，但首次装载和页面恢复仍缺完整证据；勾选须在完成本清单全部场景和宿主验收后再定。

  玩家路径：启用并建立基准 → 离开旧聊天或页面 → 返回 → 有界恢复 → 展示本次真实变化 → 下一次成功生成消费摘要。

  入口复用 `core/interceptor.js` 中 store 重载后的聊天切换通知，并覆盖扩展首次装载、页面重新进入前台的场景。进入聊天时先读取上一份有效活动基准，再决定恢复，避免先刷新基准把离线间隔抹掉。正常活动采用有界频率更新基准，以覆盖异常关闭没有退出通知的情况；不足以确定准确离开时刻时，按“距上次有效活动”表述。

  结算只选择已经登记、可以同草稿运行的事件、人物日程与势力规则；事实不足的部分明确跳过，不调用 AI 补造事实。恢复批次绑定聊天、进入序号、起始版本和时间区间。事务前复核目标仍然一致，再提交候选、批次账与摘要。重复通知合并，同一成功批次不再执行，失败保留重试基准。

  记忆锚覆盖整批，每轮完成后恢复保护子树。`maxRounds` 是离线推演截断上限：超限部分如实记为未推演，不在重复进入时再次制造同一离线批次。该规则与 S2 保留预算余窗的规则分别登记。

  交付范围包括自动入口、草稿结算适配、失败重试、锚保护、真实摘要和面板状态。首次启用只建基准；默认关闭；不触发整条包含 AI 的 after 工作流。

  验收场景包括：首次启用、短刷新、长离开、重复进入、离线期间时钟回拨、第二轮抛错、Promise 回调拒收、受保护子树真实值检查、失败后重试、恢复排队期间切聊天、同聊天发生并发更新、生成失败后摘要保留。必须检查提交后的值与落盘重载值。

- [ ] **S2 远方自动生命周期**

  玩家路径：启用并登记远方地区 → 正常游玩推进剧情时间 → 远方按完成日窗口积累大势 → 消息在途 → 到期且渠道畅通后进入听闻 → 下轮注入。

  以 SP1 确立的剧情时间为唯一依据，在实际世界时间更新后、相关快照发布前挂一个推进节点；生成前只做必要的到期投递核查，不额外推进日窗。节点复用 `farfield.tick/deliver`，与既有 `region.offline` 对齐时间和顺序，但两者分别记大势与明确事件，不互相复制内容。

  窗口预算不足时保留游标余量，下一次从尚未完成的窗口继续。零时间、倒退、重复楼层与重放不能追加未来脉搏。默认关闭；开启后首调建立起点，不凭空补写此前历史。

  封路需区分远方演化与消息可达：现有 tick 会跳过 blocked 地区，这一点在实施时要单独裁决并验收。推荐远方仍按规则积累，消息保留在途，解封后仅投递一次；若维持跳过规则，界面必须说明缺少该段模拟，不能显示为“远方一直在正常演化”。在途队列满时推荐暂停接收新的批次并报告容量原因，避免静默挤掉尚未抵达的消息；具体预算与拒收单位在 SP4 明确。

  沉积落地和事实转传维持显式操作，消息到期不自动生成事实键，也不在远方事务内调用自行开事务的沉积写口。附属节点失败记录到工作流与巡视，不阻断主生成。

  验收场景包括：真实生成前后节点、相同时间重复执行、跨多个世界日、预算只够部分窗口、冻结重放、近场不重复推进、消息未到期、封路与解封、在途容量满、关闭后零写入。核对听闻与 prompt 内容，不以调用次数替代结果；记录 AI 请求数变化为零。

- [ ] **S3 可确认的种子新局**

  玩家路径：源聊天提取并保存 → 创建种子转移包 → 目标空新聊天导入并预览 → 选择变异度 → 确认初始化 → 重载后继续游玩。

  保留 `worldSeed.sow` 的只读计划职责。优先增加显式本地导出/导入，把源聊天种子复制到目标聊天的库；转移包带格式版本、来源、结构签名和容量界限，经白名单校验接收。暂不把全部聊天存档变成扩展全局库，避免扩大读取和迁移范围。

  初始化消费者把计划中的势力、人物关系、地点、时代背景映射到现有状态字段，先建立 id 映射并检查引用完整性，再预览拟写入结构。当前种子只保留道路数量、人物显示名和关系档位，无法据此恢复原道路端点或同名人物身份；预览必须写明保留的信息层级，不能声称完整还原原地图。需要更丰富结构时，另行提升种子格式版本并说明老格式的可用范围。

  空新局判定复用 store 的默认骨架与存档来源信息，并检查世界资产、事件进度、分支继承与已有镜像，不能只看 `round === 0`。确认绑定目标聊天、预览签名、变异结果和起始状态，提交前再次核对。变异在预览时生成一次，确认应用同一份结果，不重新抽随机数。

  一次事务安装完整结构并写入初始化来源，事件、暗流、回声、编年史和推进轮次从零开始；失败不保留半份新世界。重复确认返回既有结果。源聊天状态保持不变，已存在世界的目标聊天明确拒收。宿主新聊天创建方式在实施前核对其实际 API 与用户操作流程。

  验收场景包括：保存与转移、格式不支持、转移包损坏、超限、同名节点歧义、关系悬空、跨世界观拒收、非空目标、继承分支、预览后切聊天或写入目标、取消确认、重复确认、写入失败、重载、零变异与固定随机源变异。确认后检查实际状态和注入可用性，不止检查 plan.zeroProgress。

## Alternatives considered

**继续补充仪表盘与诊断模块。** 可用现有只读接口快速增加可观测性，改动风险较低。但本轮缺口发生在调用与提交路径，新的展示面无法让离线恢复、自动远方与种子新局发生，因此排期先完成三个已有承诺。

**离线恢复直接执行现有公开 tick 或整条 after 链。** 可最大程度复用当前代码和工作流顺序。但多个 tick 自行开事务，after 链还含在线生成上下文和其他副作用，无法遵守候选草稿与整批原子性；推荐提取同草稿结算逻辑，由原入口和恢复入口共用。

**自动扫描全部聊天，建立全局种子库。** 选种子更方便，也省去显式转移。但扩大存档访问、冲突和迁移范围，对自用项目当前核心路径并非必要；优先做本地转移，只有反复跨局选种子的实际需求成立后再评估全局库。

**在巡视中自动执行生态重扫。** 更容易提供连续健康读数，但会改变既有显式扫描的成本边界；当前保留过期提示和显式重扫，只补完整输入依赖与结果消费。

## Acceptance criteria

1. SP1–SP6、S1–S3 的拟交付物与逐项验收结果分别登记；未实现、未测或环境阻塞均不能勾选。
2. 新路径通过真实产品模块与实际接入点跑正向场景；失败、串聊天、重复、容量满与取消场景有逆向验证。
3. 真源码破坏在副本上运行同款判据；锚点不存在、不唯一和判据不敏感均明确失败，测试不依赖历史绝对计数。
4. 每个实施版本跑相关专锁、module-registry、出口/死子面、拒收码、容量、测试可达、同源读数与全量回归。结果现场填写 status、通过数、失败数与候选一致性，不继承旧数字。
5. 输出过多的测试直接写日志文件，长任务保存可核对的身份；执行通道失效后更换通道，不重复调用失效环境。仅制订本计划时运行文档检查，不启动产品回归。
6. 最终在真实 SillyTavern 走完返回旧局、远方消息抵达、种子初始化与重载；保存交互、控制台与实际状态证据。mini-DOM 只作为前置验证。

## Risks

候选复制和精确审计快照随存档体积增加成本。先以代表性存档记录耗时、复制量与写入次数，再设适合手机的预算；分片优化不得把整批失败语义改成无提示半成功。

真实活动时间与现有日程、地区延迟可能使用相同毫秒表示但语义不同。实施前必须完成时间映射与旧基准迁移，否则接通自动入口会放大错误推进。

种子是有损结构摘要，现格式不足以重建道路拓扑或解决所有同名人物。初始化必须按可恢复字段作承诺，遇到歧义拒收或让玩家明确处理；不能靠猜测补齐。

真实宿主事件、空新聊天判定与页面恢复行为依赖运行环境。当前缺少实机验收证据；这限制实施后的完成结论，不妨碍本提案供评审。

历史笔记检索只有 [数据完整性修复](../../implemented/bug-fix/2026-10-04-offline-farfield-audit-integrity.md) 部分重叠。该笔记继续负责已实现的候选隔离、远方窗口与审计有效性，本提案负责尚未实现的调用编排和玩家路径；二者保留并互链，不替换历史交付记录。
