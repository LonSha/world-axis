# Agent Note: WorldAxis 从机制实体推进到连续游玩的双九项增量

Status: proposed

## Problem

用户要求优化提升与拓展创新各九项，至少三天实质开发体量，聚焦世界运转和剧情，不让守卫成为第二系统。`319356e` 的运行元数据为 2.231.6，旧 OP/IN 规划却仍以 c6ff687 / 2.231.0 把十八项列为未实施。对应实体已经存在，照搬旧清单或全部勾完都不准确。

本轮六个专项合计 172/0；补充探针同时复现未知效果被外层报修复、方法无目标仍扣工具、预约日独立、场景不按观察者/地点筛选、禁用训练仍被蓝图判为可开始。专项全绿只覆盖它自己的判据，不能替代完整玩家路径。静态发现与行为复现分别记录在[现场基线](../../../../plans/WORLD_PLAY_BASELINE_2026-10-24.md)，不把推测写成已修。

## Proposal

## Proposal
以 [WP 优化九项](../../../../plans/WORLD_PLAY_DEPTH_9.md)兑现已有行动、时间、物件、经营、共同生活与场景；以 [WX 创新九项](../../../../plans/WORLD_EMERGENCE_9.md)新增多人竞争、协作、互惠、先例、兼容、周期活动、社会记忆、承继和地方发展。正文只维护在两份计划，不在笔记复制十八项。
采用 A 人物与办事、B 地方与共同生活、C 长期沉积与地方分化三个大更新。按正常入口、实际 owner 状态、可知反馈、替代路径和重载后果结项。共同入口、时间、认知、场景、蓝图只各算一次；净工程量初估 214–322 小时，附 20% 余量和前三个有效工作日切片，绝不解释为三天交完或 AI 墙钟承诺。版本号留到实施时决定。
WP-2 的设施抢修与 WP-7 联合结项，WP-9 分为早期安装契约和后期三包整局；这些是交付分层而非额外产品项，避免所有项互相等待。复用现有 store/commit/exec/playtime 与业务 owner，不增加万能执行器、第二套事实/库存/时间或无限二阶认知。首发工艺只取游戏内机械与虚构设备规则。

## Decision
采纳面向世界机制与连续游玩体验的 WP 优化九项与 WX 创新九项框架。放弃纯治理与静态守卫扩建，转向通过纵向业务切片（A 人物与办事、B 地方与共同生活、C 长期沉积与地方分化）打通各引擎真实消费面。坚持单一真源持久化规范与向后兼容契约，杜绝第二套世界状态或万能调度器。

## Consequences
各项能力必须通过端到端集成测试（A1-A3、B1-B2、C）验收，所有新写口与读口必须在全局行动桌（action-desk）与 UI 面板形成闭环，死导出与幽灵读写被严格门禁约束。真实宿主与全链路回归耗时增加，要求每个切片都具备独立无副作用的验证手段。

## Alternatives considered

- **直接沿用旧 OP/IN 清单**最省维护成本，且模块名一一对应；但实体已经加入，旧清单无法说明还缺哪条正常玩法。采用新 WP/WX 编号并保留旧项映射，既不抹历史也不重复卖模块。
- **只修五个探针缺口**最容易快速验证，能立即改善真实错误；但只修返回值/过滤仍达不到用户要求的大型世界机制计划。把这些修复纳入相应纵向工作包，并设置连续游玩下限，不能修一行就整项勾完。
- **再新建十八个引擎**最容易展示规模，但会继续增加有 API 无正常消费者的孤岛。先复用原 owner，只有没有合理归属的新语义才在实施中讨论新模块；文件数不作为目标。
- **全面修旧笔记与建立自动规划治理**能让校验输出更整洁，但偏离世界玩法主线。此次保存旧错误基线、要求新内容合规与不新增失败，不改无关笔记，不新建 CI、看板或计划生成器。
- **把至少三天当作三天固定交付期**表面符合数字，却压缩了十八条跨模块路径的实际工作。以净工程小时、共享工作去重和三包完成条件估算，实际实施后再校准，既不空等也不虚报。

## Acceptance criteria

1. WP-1～9、WX-1～9 连续唯一，严格十八项；每项有现有基础、必须交付、完整玩家路径、结项下限、依赖、边界和工程估算。
2. 现场证据区分静态、无头行为、宿主与玩家层；六专项和五组观察可复算，不以 probes 的 observed 表示产品修复。
3. A/B/C 排程与两线预算加和一致，共享工作只归一个条目，部分交付明确标注；不把测试/守卫另列功能名额。
4. 当前入口与两份旧 OP/IN 规划均能找到新计划；旧文字保留其历史时点。新笔记格式合规，改动链接有效，笔记全树相对基线不新增失败。
5. 本次只交规划及证据，不改产品/现有测试/配置/版本，不运行全量回归或声称宿主通过。按用户授权提交并推送到原远端 master，最后核验远端哈希；推送失败必须如实报告。

## Risks

范围很大，估算不是承诺，A 包实施后须重估剩余；不能为了赶期用标签或返回值替代真实兑现。依赖中的旧 owner 若不支持所需语义，调整该业务契约而非建立万能总管。未知信息、群体解释和时间安排都需控制在相关人/地区与当前事项，不把整个世界复制进每个角色。

真实宿主、手机和长期续玩仍未验证，只有获得对应环境证据后才可结项。笔记树仍有四条旧坏链接与旧格式问题；本轮保留并比较错误集合，不声称全树全绿。探针作为基线观察会在修复后改变结果，未来维护者不能为维持旧观察而回退产品。
