# Agent Note: V12 全域活世界升级

Status: proposed

## Problem
用户否定以门禁、报告和常规维护占据版本计划，明确要求覆盖全部引擎与内容的重大产品提升。原 V12 范围偏工程流程与期刊，不能代表整个项目。源码核对也确认 life、research、production、intel 等已有实体，不能把既有功能包装成新增能力。

## Proposal
采用九大域深化与九项跨域体验组成超级版本；计划见 [V12 总纲](../../../../plans/V12_MASTER_PLAN.md)，静态覆盖账见 [全文件覆盖](../../../../plans/V12_ENGINE_COVERAGE.md)。覆盖 295 个引擎及 actors/core/render/ui，共 338 个顶层 JS 文件。分工为初始归属，各项仍待能力深审，不把标题检索当作行为缺陷证据。

以城镇短缺、失约、远行归来、时代转折和多视角信息差贯穿人物、事件、社会、地理、认知和表达。工程模块支持玩法路径，不强行新增机制。


## Decision
确立全域活世界超级版本路线：分五大推进批次（A～E），以 18 项宏观成果为主干。遵循现有写口与单一真源，不新建孤立数据模型，通过真实场景贯通（城镇短缺、一次失约、远行归来、时代转折、同一真相多重叙述）。
## Consequences
既有 295 个引擎和四大核心目录由浅入深按批次重构与接入；禁止以测试通过冒充产品完工，禁止以静态索引冒充语义深审；所有升级需提供真实消费者验证。
## Alternatives considered
- 延续期刊与工程流程计划：范围易控制，但不符合全项目跃迁目标，放弃。
- 每引擎各加一个功能：易量化覆盖，却会增加孤岛和运行成本，放弃。
- 一次重写全部模块：能统一风格，但损失既有契约、存档兼容和已实现能力，放弃；采用按域深化、真实场景贯通。

## Acceptance criteria
逐文件完成能力、短板、消费者、状态归属与迁移说明；升级成果必须体现在玩家选择、世界变化或内容质量，不把文件改动数量当成果。总体设计落盘不等于实现完成。

## Risks
覆盖账来自静态枚举，仅涵盖五个目录的顶层 JS，不能声称全仓资源已审计。新增玩法必须先检查既有实体，避免重复状态。V11 局部交互和外部供应商未验边界继续保留，不能因新计划而宣告已通过。
