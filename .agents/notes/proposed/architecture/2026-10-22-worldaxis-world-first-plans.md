# Agent Note: WorldAxis 从治理中心转向世界机制与差异化体验

Status: proposed

## Problem

用户要求基于真实仓库制定优化/创新各九项，并明确指出守卫已挤占项目主题。代码基线 c6ff687（2.231.0）已拥有行动、成长、物件、生产、研究、家庭、因果、制度和多轮实验室；简单再列模块名会重复建设。研究/家庭与正常玩家入口之间还有明显连接缺口，蓝图机制导出只覆盖四个引擎的 enabled，life.decide 仍以固定条件顺序返回动作。

本次修复只经四个相关专项证明，按用户指令未跑全量回归。代码已经本地提交，但首次推送因缺少 Git 凭据失败；规划状态不依赖推送成功而冒充已实施。

## Proposal

[优化九项](../../../../plans/WORLD_PLAY_OPTIMIZATION_9.md) 负责让现有机制共同改变行动与后果；[创新九项](../../../../plans/WORLD_INNOVATION_9.md) 负责新的动机/社会认知/技术与制度演化规则。正文只保留在两份计划，不在本笔记复制十八项台账。

采用三个大更新：人物与知识、社会与地方、历史与时代。差异化来自有限时间和有限认知通过协作、传承、建设积累成有路径依赖的世界，不以模块数、导出数或守卫数量衡量。所有项包含玩家入口、实际结算、可见后果和续玩；必要测试/兼容是功能内部工作，不另占产品名额。保留跨题材可选启用和既有单一真源，不新建万能规则 DSL、全知社会 AI 或第二套调度/存储。

## Alternatives considered

- 继续沿用旧治理计划最稳妥，能复用大量检查，但当前缺口是正常行动不消费机制；因此不再把守卫升级、审计平台、计划生成器扩容列入下一轮功能主线。既有正确性约束仍保留。
- 直接新建十八个引擎最容易展示规模，但会把孤立模块问题再扩大一次；按业务纵向链安排大更新，能在旧 owner 内实现的就不新增 owner。
- 将实验室/世界日程/地图当作创新很容易形成清单，但这些已有实体和真实函数。特别是 worldLab 的旧头注释遗漏 simulate/adopt/advance，不能抄注释下结论；创新 IN-2 转向角色自己的预期与事后学习。
- 声称全行业首创能强化宣传，但未作行业穷尽检索，也不能从本仓零命中推导首创；明确为本项目机制组合的差异化。

## Acceptance criteria

两份计划编号分别 OP-1～9、IN-1～9，恰好十八项；每项含现有边界、新增行为、依赖、玩家验收。用 c6ff687 而非旧计划勾选建立基线；静态发现不冒充实机结论。实现后的完成结论必须区分业务专项与真实宿主体验；当前不执行全量回归，也不把写计划视为实现创新机制。

本次只检查文档编号、链接与笔记格式，规划提交不修改产品/测试/版本。更新 NEXT_PLAN 的当前入口，旧计划保留为历史，不把历史全绿数字移作本次验收。不新增 CI、看板或计划同步框架。

## Risks

十八项覆盖多条长期业务链，依赖最重的 IN-9 必须最后用可玩纵向场景交付，不能先写时代标签。IN-2/3 若无限扩展人物认知状态会拖慢手机，需限制关键决策、相关对象与模拟视距；限制内置于玩法，不发展独立治理系统。没有实机验收就不能声称首屏、切聊天和长期续玩已通过。
