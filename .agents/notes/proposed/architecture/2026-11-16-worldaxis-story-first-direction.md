# Agent Note: WorldAxis 故事优先双九项方向

Status: proposed
## Problem
WorldAxis 已积累大量生态、产业、人口、后台推演和治理能力，但这些能力没有稳定组成用户真正需要的体验：用户推进正文时，镜头外人物继续行动，行动留下可发现的线索，玩家可以介入并承担不同选择的后果。继续按“增加模拟系统”扩张会提高注入、token 和管理成本，却不一定让正文更像真实世界。

另一个高风险是常识断裂：人物瞬移、越权知情、物品和动作状态不连续，以及模型被截断或路由漂移时无法解释。已存在的 `living-world`、`backstage`、`elsewhere`、`act`、`world-diary`、`investigation`、`foreshadow`、`model-receipt` 和 `token-budget` 说明项目并非缺少所有底层能力，真正缺口是体验主链、边界约束和可见反馈没有收口。

## Proposal
以 [拓展九项](../../../../plans/WORLDAXIS_STORY_EXPANSION_9.md) 和 [优化九项](../../../../plans/WORLDAXIS_STORY_OPTIMIZATION_9.md) 作为新的 18 项产品计划。主线收敛为“正文推进→场外行动→可见痕迹→玩家介入→选择后果→重新进入正文”，而不是继续建设需要用户管理的世界生态模拟器。

第一阶段优先打通正文推进回应、重要 NPC 持续行动、行动痕迹、位置移动连续性和注入减负；第二阶段补齐伏笔/暗线、支线、分歧后果、人物记忆、知情边界、动作与物品连续性；第三阶段补齐失约重逢、从人物/线索页介入和破甲、反截断、查降智、模型路由工具。

所有新行为复用现有 owner 和单一真源。模型只能提议或表达，不能凭叙述直接越过行动、位置、知识和物品的真实写口。门禁、台账和测试属于验收支撑，不占 18 项名额，也不作为默认用户体验。

## Alternatives considered
- **继续扩展世界生态模拟器** — 能覆盖更多社会和经济机制，且已有大量引擎可承接；但会把复杂度暴露给用户，不能保证镜头外行动能被发现、介入并改变后续，因此不作为主路线。
- **只修常识问题，不做故事闭环** — 可快速减少瞬移和全知，但人物仍可能静止，伏笔和选择无法形成可玩的反馈循环，因此只作为优化线，必须与正文主链并行。
- **全面重写后台世界状态** — 有机会统一概念，但会破坏已有存档和 owner 契约，且无法证明体验提升；采用增量接线、先审计已有能力再补缺口。
- **把全部已有引擎默认开启** — 能让世界看起来更活跃，但会增加噪声、注入负担和模型成本，也混淆 v2.517 引擎策略与产品默认体验；不采用。
## Acceptance criteria
1. 仓库存在拓展九项与优化九项唯一计划，合计严格 18 项，门禁不占项。
2. 第一阶段场景可观察：玩家推进正文后，非在场重要 NPC 继续行动；行动产生至少一种可见痕迹；痕迹带时间/地点/来源/可靠度；人物不会无过渡瞬移。
3. 玩家可从正文、人物页或线索页进入至少三种处理（寻找、核实、暂不处理），不同选择造成真实不同后续，而不是只改文案。
4. 位置、知识、动作、物品和注入内容均有单一 owner；未知状态保留未知，不由模型或 UI 猜测补齐。
5. 计划提交并推送后再进入代码实现；每个实现批次以用户场景验收，专项测试只证明对应行为，不以测试数量代替产品完成。
6. **Ruby 宇宙卡是专用验收卡，不得被改写、裁剪或为测试而关闭其既有机制。** 单元测试可以使用小型夹具，但产品级验收必须在 Ruby 卡的真实世界书、MVU/Tavern Helper 脚本、正则脚本、状态栏和长上下文环境中复现。
7. Ruby 卡测试采用不可变外部输入：以路径/环境变量接入卡文件，记录哈希与结构画像，不把约 96 MB 卡文件复制进仓库；卡版本、世界书条目数和脚本数量发生变化时重新生成画像并人工确认，不静默覆盖基线。
8. Ruby 卡验收至少覆盖：正文推进后的场外行动、可见痕迹/消息、位置连续性、知情边界、选择分歧、注入预算与模型路由诊断；不能用“插件 API 能调用”替代真实宿主路径。


## Risks
已有 `living-world.autonomousTick` 和 `backstage` 可能只是可调用能力，尚未形成稳定的完成驱动调度；不能把入口存在误报为闭环完成。异步模型推演与正文推进之间存在完成时序问题，必须使用已提交快照、幂等和明确的 deferred 状态。位置和知识约束若过严会阻断合理叙事，因此应允许在途/未知/误会/谣言，而不是强行给出唯一真相。

复杂生态默认收缩可能使旧用户感觉部分内容“不再自动发生”，需要保留显式开关和迁移兼容。模型回执、token 用量和 TPS 可能受供应商字段差异影响，缺失时必须显示未知而不是推断。
