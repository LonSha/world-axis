# Agent Note: 立项 WorldAxis V10 全景双九项演进纲领（OPV10-1～9 + EXV10-1～9）

Status: proposed

## Problem

在顺利交付 V10 Release Readiness 发布准备计划后，系统的机制底层虽然极其庞大（290 个引擎，114 个具备 buildBlock 导出），但在推演注面与玩家一屏控制上存在“散落与未完全聚合”的短板。大量核心系统（外交条约 diplomacy、因果报偿 karma、日程事件 events、异地远方 elsewhere、区域经济 economy、离线沉淀 offlineTick）未直接打通正文主推演管道，且 pending 待办分散在 12+ 个模块中缺乏单一只读聚合，玩家在面板上难以一眼看清全貌并下钻操作。

## Proposal

正式立项并启动 **WorldAxis V10 全景双九项演进纲领**（合计 18 项机制：优化九项 OPV10-1～9 + 拓展九项 EXV10-1～9）：
1. **优化九项 (OPV10-1～9)**：打通外交（diplomacy）、因果（karma）、日程事件（events）、异地（elsewhere）、经济（economy）、离线（offlineTick）的正文精准注面与自适应动态降档，构建 `core/unified-pending.js` 统一待办聚合服务与审计加固。
2. **拓展九项 (EXV10-1～9)**：落地面板「外交看板」、「因果天平」、「大事件日历」、「异地雷达」、「行商集市」、「待办与抉择」一键下钻工作台，以及谣言网络与多势力博弈动态推演。
3. **闭环验收 (EXV10-9)**：编写 `tests/v10-master-matrix.js` 达成 18/18 真实无桩矩阵全绿。

## Decision

1. 遵循仓库双九项（18 项）演进传统，在 `plans/V10_MASTER_PLAN.md` 建立唯一纲领真源，并同步更新 `NEXT_PLAN.md` 当前入口。
2. 保持**双项目双计划收口前严禁全量回归**的铁律纪律，开发实施期间只执行定向专项、真源破坏两向自证与局部矩阵验收。
3. 严格禁止形式主义打卡或伪造桩函数，每个新机制均保证真实内核、接线、持久化与面板交互闭环。

## Alternatives considered

1. **直接宣告发布并不做 V10 双九项**：这会违背用户明确推进 V10 的工作指令，且留存了未打通的注面与分散待办短板，因此不选。
2. **仅做 3-4 个轻量 patch**：碎片化的修改无法形成系统性沉淀，容易造成命名空间漂移与账本不平，因此坚持双九项 18 项大体量体系推进。
3. **在推进新功能时触发全量回归**：这会违背用户反复重申的铁律，浪费 30+ 分钟宝贵时间，因此坚决冻结全量直至整体收口。
4. **新建平行状态系统而不是复用既有 290 引擎底座**：这会破坏既有单真源状态契约，必须严格在既有 store/engine 上做正交打通与聚合。

## Acceptance criteria

- `plans/V10_MASTER_PLAN.md` 完整登记 OPV10-1～9 与 EXV10-1～9 共 18 项机制。
- `tests/o7-plan-tree-gate-v2187.js` 笔记树门禁 69/69 全绿通过。
- 18 项机制全部具备独立定向专锁或矩阵验收断言。
- 最终产出通过 `tests/v10-master-matrix.js` 取得 18/18 PASS 凭据。

## Risks

- 多源并发注入可能导致上下文超出预算：通过 OPV10-8 自适应动态降档机制保证高优先级事实不被挤出。
- 待办聚合可能引入循环依赖：通过 `core/unified-pending.js` 纯只读拉取与惰性调用保证解耦。

## Consequences

- 系统将拥有全仓首个统一待办中心，彻底解决 30+ 引擎待办散落的问题。
- 正文推演将具备外交、因果、日程、经济与异地羁绊的深层生命力。
- 严格遵循门禁纪律，不产生任何读数漂移或未登记死导出。
