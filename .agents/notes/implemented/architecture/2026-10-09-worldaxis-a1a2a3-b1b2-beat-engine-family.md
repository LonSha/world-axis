# Agent Note: WorldAxis v2.189.0 —— 拍引擎家族（A1/A2/A3 + B1/B2）的边界取舍
Status: implemented

## Problem
本仓的编排面是**单向下发**的：`chapters` 开章、`campaign` 定阶段、`beat-mask` 遮未来拍、`rhythm-loop` 推相位 —— 全都在「往正文塞要求」。而正文交回来的东西**只有两种处置**：当没发生（继续推进），或整章重排。

三个缺口在现场实测（`engines|core` 零命中）后被确认：

1. **「演得出来，但缺一步因」与「根本立不住」长得一样**。前者只需补一句铺垫（零成本），后者才该打回重写；合成一个「不通过」之后，用户看到的是模型被反复重排，而真正缺的那一步因永远补不上（`缺铺垫`/`自裁量` 零命中）。
2. **本仓有「章」「阶段」「相位」，没有一个「拍」**，更没有一处回答得了「谁在推进拍号」—— 于是「模型顺手把当前拍改到第 5 拍」与「引擎推到了第 5 拍」在状态里长得一模一样。
3. **往后没演的那些，在已经发生的这些事之后还成立吗** —— 没有一处回过头问（`复验`/`篇章检查`/`unwritten` 零命中）。本仓的《主角不去救、后文却按他已经救了写》只能等演到那一章才炸。
4. **「这一刻同时允许几件事冒出来？」** —— 本仓有许多「每 N 轮做一次」的自主面，各自很克制，但没有一处回答这句话（`minGap`/`跨线` 零命中；`proactive` 的 `COOLDOWN_ROUNDS` 是同一个 NPC 连续拉动的冷却，语义不同）。

缝合来源：SnowIII/story-director（MIT）的四组口径 —— 合理性审查三档 / 篇章检查 / 节奏控制两条铁律 / 四道「别一直生成」的闸门与防重复名单。

## Decision
新建四个引擎，每个只做几件事，每件一个硬条件，全部默认关：

- **`engines/beat-report.js`（A1）**：四值白名单 `pass/adjust/setup/reject`，表外一律拒收且**不做宽容降级**（降级会让「实在立不住」被静默折成「微调」）。`adjust` 必须给 `purpose` 且 `keeps !== false`（缺则 `missing-purpose`、换了目的则 `purpose-changed` —— 那是换了一拍，必须走 `reject`）；`setup` 必须给 `need`（否则不按住 —— 不说缺什么等于把一拍无限期悬起来）；只有 `reject` 计数，两次打回间至少隔 `minGapRounds` 轮，同章累计 `strikesPerChapter` 才去改篇章、同章最多改一次（达上限后如实拒收 `redesign-exhausted` 但**计数照落**）。
- **`engines/beat-ledger.js`（A3）**：拍号**由引擎推进** —— `claim()` 与引擎账不符一律拒收并留痕（`overwrites`/`lastClaim`，自改必须可查）；已落的拍**不得改写**（`landed-immutable`）；换场必须先给过渡（`hard-cut`）。
- **`engines/plan-audit.js`（A2）**：**纯只读**（真代码面零 `store.transact`、零 `draft.`、导出面没有 `buildBlock`）。三态分开报（`stands`/`needs-adjust`/`unreadable`），依据面只读已归档的三处事实源 —— **「你还没做 ≠ 不成立」**。
- **`engines/gen-gate.js`（B1+B2）**：四道闸门**按轮记账、绝不看墙钟**；`gate` 只判不记、`record` 先过闸门再落账；`chapter` 两档**豁免整机闸门**（收尾是既成事实）；防重复名单**记正文不只记标题**。

四个引擎的拒收码共 16 个，**零进基线**，全部在 `tests/reject-v2780.js` 里用真 API 跑出可执行见证（先跑 `tools/probe_reject189.js` 看真返回再照读数写）。

## Consequences
正面：
- 「缺一步因」与「立不住」第一次分开处置，缺因能被补上而不是靠重排；
- 拍号从模型手里收回引擎，节奏不再被偷偷踩油门，且自改可查；
- 往后安排能在旧章刚完时被回头核一遍（这正是「我明明没帮忙，她却安然度过」那类问题的解药）；
- 「同时允许几件事冒出来」第一次有了可判定的答案，并逐档报是哪一道卡着、还要等几轮。

代价与边界（如实登记）：
- **面板侧实机未验**（无头回归不装载 `ui/panel.js`）。四个设置读口在 O8 消费者登记表里如实登记为「程序化接口」—— **登记不是豁免**，面板接线后应改为真消费者。
- 两个新注入源进 `inject-budget` 的 PRIORITY / ACCOUNTS 后折叠策略随之生效，但「折叠后正文读起来是否更顺」属**内容质量面**，本版不判。
- 本版**现场修出一个真缺陷**：`gen-gate.roundOf` 原先走 `inputGuard.count`，而 `count('abc')===0` 把所有坏输入塌成 0 ⇒ `bad-round` 在那个引擎里写得出、跑不到。已改严格判定（专锁 N1 双向自证）。
- 另一处**按事实而非放宽判据**的微调：`beat-ledger` 的入参名 `o` 落在 v2390 幽灵读点扫描器的标识符集内，已改名 `opt`；**没有放宽扫描器**。

## Alternatives considered
1. **把三档合成一个「不通过」** —— 拒。那正是本版要治的病：合成之后缺因永远补不上，且「实在立不住」会被静默折成「微调」。
2. **让 `claim()` 直接改台账（宽容对齐）** —— 拒。那等于把「谁在推进拍号」又还给模型，退化回「两件不同的事在读数上同形」。
3. **让 `plan-audit` 把复验结果落盘** —— 拒。复验结果**必然过期**：世界一动，那份「还成立吗」的答案就变成假账。故它全文零 `store.transact`，且导出面没有 `buildBlock`。
4. **把闸门账与名单放进 store 骨架** —— 拒。它们**不是世界事实**（同 `presetWorld`/`perfLedger` 两条先例），不该进存档、也不该在 `evict.SITES` 里假装是个 store 环形容器。
5. **闸门看墙钟而不是轮次** —— 拒。上一次「真实时间与剧情时间混算」的代价是离线间隔被整平（v2.161.0 TP3）。轮次取不到就 `bad-round` 拒算，不退回墙上时间。

## 收口轮的新增记录（全量回归后补记）

首次全量回归跑出 **17 处红**，它们不是四个引擎的行为缺陷，而是「新引擎进来之后，周边没有跟上的面」——正是本仓「同一件事在多处各写一遍，改一处不等于改全」那类账。逐组处置：

| --- | --- | --- |
| 拒收码手册 | `docs/ERROR_CODES.md` 停在 788 码，缺本轮 16 个新码（7 处同源红） | 按 `tools/gen-error-codes.js` **重生成**（不新增数据源）⇒ 804 码，双向零缺零余 |

| 零读命名空间 | 停在 23（实测 25） | 走既有 `tools/sync-e2e-readings.js --write` 回填，`--verify` 零失配 |

最终：`node tests/run.js` → **通过 15852 / 失败 0**。

一条值得留下的形态观察：**这 17 处红全都不是「新代码写错了」，而是「新代码进来之后，没人通知的那几处旧读数」**。其中 v2830 那三处尤其典型 —— 它们是写死的、不在 `readings` 族扫描面内、也没有任何判据盯着的数字，因此从 v2.185.0 起一路红到本轮全量才现形。判据的覆盖面（「谁盯着这个数字」）与数字的存活期（「它多久会过期一次」）必须对齐，否则「跑一次全量才看得出」就成了这类账唯一的发现通道。
