# Agent Note: V9 选材额度、变化区间与末态续接

Status: implemented

## Problem
结构汇流只有字符约束，已有 incrementalCost 量的是毫秒而非 token；零候选也不能区分尚未采集和有状态但无适用材料。玩家需要看成功推演的变化，而不是重复全表。V8 格局种子故意不移植来源历史，因此不能把“从归档末态继续”偷偷塞进原先的新局语义。

## Decision
collector 使用 injectBudget.tokensOf 的同一估算口径，新增默认 0（不限制）的 maxTokens 选材上限，整行选入，保留尾部约束；最终全局共享池仍由 render 单次裁决。候选输入与输出分别记账，不把本地选材额度称为分配给该源的独立预算。诊断区分 disabled、not-collected、正常零候选及 state-but-no-candidate，后一种只是五 owner 汇流无适用材料，不证明全世界注入坏了。

worldChanges 默认关闭，在推演发出前和成功结算、分发及暗流推进后读取固定五类公开投影指纹。仅保留一份固定大小的本次区间摘要，不建历史和第二真源；只报数量和登记变化，隐藏暗流与私密研究不参与。无成功快照不冒充零变化，非当前聊天或非当前轮的摘要不注入。它不是全局任意手动编辑的事件流；同轮再次推演会覆盖该次区间读数。

续接与 V8 格局新局明确分模式。周期作品额外保存有界末态：人物身份及已登记关系、暗流当前阶段及原文；不移植纪事、情报、记忆、排期、照护和研究。选择已有归档末态后导出作者私密续接包，跨聊天仍经过 worldSeed 目标空局预览与显式确认，确认在一个事务中落人物关系和暗流；轮数重置为 0，托管关闭并清理来源推进基准。旧格局新局包和历史附件规则保持不变。续接载体在种子库留 continuationRequired 标记，重载遗失内存末态后须重新导入原包，直接格局预览及丢失末态的种子导出均拒绝，不能静默降级。

## Alternatives considered
- 用 incrementalCost 给 token 定额：可直接复用已有函数名，但单位是毫秒，不能成为选材依据。
- 用渲染时前后差分当本轮变化：接入少，但两次渲染之间的写入不属于同一个推演；采用推演边界快照并显式标注区间。
- 将归档全文恢复成新局存档：保真最高，但会移植旧 chatId、过期时钟、回执和私密知情边界，破坏新局隔离；采用白名单末态续接，承认它不是完整存档恢复。
- 在 worldSeed 确认后另开事务补暗流：能少改 owner，但第二次事务失败会留下半初始化目标；续接计划并入同一个 owner 确认事务。

## Consequences
新增选材限制不改变旧配置行为，token 是估算而非模型实际账单。变化指纹存在散列碰撞的理论漏检风险，仅用于观察，不参与世界写入决策。续接比格局种子保留更多进度，但不保留全部机制状态，UI 和包内必须明确列出不保留项。作者私密包不能当安全公开摘要。
