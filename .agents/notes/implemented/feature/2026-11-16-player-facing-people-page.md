# Agent Note: 玩家面人物页与底层工作台折叠

Status: implemented

## Problem

人物页原本直接把关系数值、关系六型、身份对照和大量人物调度写口放在首屏。面板的主要使用者是玩家，而不是调试者；这些内部读数让玩家难以回答最基本的问题：故事里有哪些人，以及我和他们现在是什么关系。

页面清单 `PAGES` 与 `PLAYER_PAGES` 受冻结测试保护，因此不能通过新增页签解决信息分层。

## Decision

玩家模式在既有 `people` 页内先渲染一个只读的叙事人物面：人物卡显示姓名、由既有关系档位转换出的关系句、信任/牵连的叙事句和标签；空状态只显示“还没有遇见谁”的引导。已有记录锚点继续使用 `people:<存档键>`，避免历史检索跳转失效。

原 `renderPeople()` 不删除、不重排，在玩家面下收进默认折叠的“人物档案与底层调度”区；开发者模式直接继续使用原渲染结果。新模块 `ui/pages/people-page.js` 只读 `store`、`registry.relationBands()` 与 `relationTemp.network()`，不写世界、不落盘、不增加控件或页签。

## 联系与同场

手札与完整人物页复用 `contactForm` 和 `bindContacts`，由邀约和口信引擎负责写入。表单携带渲染时的聊天键，切聊后不允许向新聊天补写旧表单。最近出场只用于排序；只有双方都有到达记录且地点相同才能列为同场。无玩家关系时不借用第三人的关系，数值缺失不参与排名。

口信的可投递轮次不是送达证据。「远方」按本聊天的逐信记录展示自己发出的信、已收到的信及实际回信，不从全局计数推测，也不为 NPC 代写回复。当面交信需要达到轮次并与收信人同地；由口信引擎写入，再读回同一条记录。

手札「此刻」以本聊天最近一封玩家可见的口信作为重开入口。起草下一句时重读聊天和信件，不把渲染时的回执当成点击时的事实；草稿追加在输入框，不发送，也不触发投递、回信或模型调用。未送达的来信和 NPC 私信不构成玩家已知信息。

「此刻」以位置引擎的在途或中止状态优先于过去的到达记录。偶遇不直接展示原始流水：手札和提示词共用同一个亲历筛选，只有近期玩家参与并与对方相互察觉的记录才显示。手札只省略提示词标题，不维护第二份历史；切聊、过期或回退后重绘即随存档变化。

## Alternatives considered

### 继续把所有数值放在首屏

实现成本最低，也不会引入新的渲染出口，但继续把引擎内部结构暴露给玩家，无法解决首屏杂乱和叙事语义缺失的问题。

### 新增一个“关系”或“人物故事”页签

信息架构更直观，但违反冻结的页 id/顺序和玩家导航测试，也会把玩家页继续变长。页内折叠能保留旧能力，同时不改变导航契约。

### 删除旧人物工作台

可以获得最干净的玩家页面，但会破坏已有作者调试入口、控件绑定和相关回归锁。保留为默认折叠区的代价更小，也给开发者模式提供稳定回退。

## Consequences

收益：玩家首先看到人物与关系语义；没有人物时不会出现一长串空的诊断控件；开发者模式和旧 DOM 仍可用；导航页表不变；关系档位继续由 registry 真源提供，避免 UI 自己复制阈值。

代价：玩家模式仍然能展开一整套旧工作台，页面源码和渲染成本没有减少；关系句是面向玩家的离散文案，需要在关系档位扩展时同步检查文案映射；玩家面暂时没有把所有人物模块的事件摘要都聚合进来。

验证：需通过 `node --check ui/pages/people-page.js`，并运行现有 UI 门禁与人物相关测试；至少覆盖全新/玩家、全新/开发、已开局/玩家、已开局/开发四种渲染情形。
