# Agent Note: 独立出刊期刊引擎与最小阅读入口

Status: implemented

## Problem
WorldChronicle 提供世界内定期刊物，本仓日程和纪事不承载刊物正文。期刊需要与世界事实分开，避免生成文章成为权威剧情。

## Decision
periodicals.js 使用 store.periodicals 的 defs/ issues 数组，配置最多 8 本、往期全局保留 48 期。配置默认关闭，启用后经 inference 通道生成。只取不晚于 clock.iso 的最近一期，不批量追补历史。无剧情日期或真实聊天时拒绝生成。消息接收后异步调度，不 await 网络请求；同聊天同刊同日期使用在途锁，提交前检查聊天、日期和配置仍一致。用户通过健康中心配置 表单、阅读转义后的正文。正文标注非权威事实，不写 worldFacts。

## Alternatives considered
聊天 metadata 是上游现成存储，但会绕过本仓 store 真源。单独日历状态会引入日期漂移，因此日期运算只计算、不存另一只钟。只做引擎会缺少真实配置和阅读消费者，因此补最小入口。同步 writeBounded 只能事后计量，不能中断阻塞，因此不声称提供写入超时隔离。

## Consequences
有界正文归档和默认关闭控制成本；日期跳跃只生成最近一期。无带剧情日期的公开事实时仅用刊物设定，日常内容可能较泛。16 项定向测试覆盖去重、短月、失败重试、串聊天防御、默认关闭与转义；受控写口测试不等于真实存档持久化证据。异步归属复用 store.claimAsync/settleAsync，纪元及依赖变化拒收。仅 scope:public 且 storyDate 合法、不晚于出刊日的 worldFacts 可进入素材。真实宿主受控写口与 API 验证 7 项；真实 store 隔离上下文探针超过 25 秒未完成，原生 ST 聊天文件持久化仍未验收。
