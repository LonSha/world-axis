# Agent Note: 设置声明必须有生产消费点，世界状态容器必须在骨架物化

Status: implemented

## Problem
本仓存在两类互相独立但后果相同的历史欠账。第一类：41 个设置登记表的 def 子键只有声明、没有生产代码消费点，用户改配置得不到行为变化，容量、衰减、阈值等承诺全部落空。第二类：40 余个生产引擎把持久数据写到世界状态一级键，但 `core/store.js` 的 `defaultWorldState()` 没有声明这些键；冷启动后直接写会因目标键不存在而失败，旧存档也无法由 `ensureShape` 补齐。

## Decision
设置登记表中的每个 def 子键必须至少有一个真实生产消费点。设置含义按引擎既有行为解释，默认值与旧硬编码逐数值等价；容量类设置统一为「新建超限拒绝、存量仍可更新、保留类按上限裁剪」。

世界状态的持久容器由 `core/store.js` 的 `defaultWorldState()` 作为唯一真源物化。本批物化 43 个容器，结构沿用各引擎 `ensure` / `openStore` 的既有默认值。`ensureShape` 继续负责旧存档补齐；`OWNED_TOP_KEYS` 只登记本地对象撞名，不用于代替世界状态字段声明。

## Alternatives considered
- **给死键加豁免名单** — 豁免能快速让扫描变绿，但用户仍无法通过设置改变行为，只会把不可见缺陷藏进台账，因此拒绝。
- **把骨架外键全部登记进 `OWNED_TOP_KEYS`** — 这能消掉门禁红灯，却让真实世界状态继续在冷启动时缺失，并把结构性缺口伪装成本地变量误报，因此拒绝。
- **在每个引擎首次使用时懒创建全部容器** — 能避免部分冷启动失败，但会保留多份默认结构真源，旧存档补形与结构审计仍不可信，因此统一在 store 骨架物化。

## Consequences
- **收益**：41 个死键降为 0；设置改值可由行为级测试观察；43 个持久容器在冷启动与旧存档载入后均存在；骨架归属门禁不再出现生产写侧越界。
- **代价与已知上限**：世界状态一级键由 151 增至 194，存档体积略有增加；容器具体子项仍由各引擎维护，骨架只负责一级容器与默认形状。若未来新增持久一级键，必须同批物化，不能依赖引擎内懒创建。

## Verification
- `node /tmp/deadkeys.js`：扫描结果 `count=0`。
- `node tests/settings-consumption-regression.js`：68 项行为断言通过。
- `node tests/world-state-materialization-regression.js`：43 容器、旧存档补齐、用户数据保留与重新初始化隔离通过。
- `node tests/field-liveness-gate.js`：骨架 194 个一级键，读侧越界 0，生产写侧仅余已登记的 `ui/panel.js::innerHTML` 本地变量误报。
