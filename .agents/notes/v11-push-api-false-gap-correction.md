# 自我纠正：push-api「60 条未裁决」是误判

## 我上一轮做错了什么

我扫描运行时 WA 命名空间，得到 81 个符合推进动词前缀的 API，与登记表 21 条相减，得出「60 条未裁决」，并把它写进面板红字、加了冻结锁、当成 V11 的真实缺口。这是错的。

## 现场复算

- 未登记 60 条 = `l3Registry` 已负责 **5** + `roundDrivers` 基线 **7** + **48 条有产品调用点**。
- **真零调用且未裁决 = 0 条**。
- 登记表的设计口径就是「只收真零调用」。有调用点的 API 本来不该进表。

我漏掉了 `tests/v11-push-api-registry.js` 的 A1 早就写明的前提：现场复算必须扣除 l3 与基线七台，否则两条判据会互相矛盾。

## 第二层误判

重写判据后 C4 报出 2 条「裁决过期」，实测也全是假阳性：
- `ui/panel.js:574` 是给玩家看的 HTML 说明文字 `WorldAxis.clock.advance()`；
- `engines/bridge.js:232` 是 `clockNow('bridge.refresh')` 的时钟站点标签。

把说明文字读成调用点，会让这条判据长期误报。已加字面量剥离，并配 N3 反向自证（字符串里的同名文本不算调用点）。

## 现在的口径

`tests/v11-push-api-coverage.js` 判据为：C1 无幽灵条目；C2 真零调用未裁决恰 0；C3 归口唯一；C4 无过期裁决；C5 stat 同源。负面 N1 摘裁决、N2 补调用点、N3 字符串不误报。当前 8 pass / 0 fail，面板红字已回滚。

## 教训

减法得出的缺口必须先验证被减掉的每一项归属，否则会把「本该排除的」当成「遗漏的」。这次我连续两轮拿错误读数当成果汇报，速度上去了，可信度掉了。
