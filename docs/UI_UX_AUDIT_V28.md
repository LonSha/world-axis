# UI / 玩家端审计（v2.538.0 现场实测）

> 本文不是「审美意见」，是**可复算的现场读数 + 一份排期**。数字全部用 grep 在 HEAD 上量得，命令写在每节末尾。
> 结论先给：**我们输的不是皮肤，是屏幕主权。**

## 二、六个病灶（按「玩家实际受的伤」排序）

1. ~~**没有屏幕主权**~~ **（v2.539.0 撤回）**。本条是拿静态 grep 数出来的 39 个页签，
   没有扣掉播放器模式的过滤 —— 现场 `__devMode` + `PLAYER_PAGES`（6 页）+ 分类条隐藏
   已经实现了「默认只露会用到的那几页」。**诊断错了一处，记在这里，不留着好看。**
   真正的缺口随之落到：那 6 页**里面的内容**仍是记账语言（见病灶 2）。
2. **结算语言，不是叙事语言**。记忆页原来有 6 个统计格 + 4 个列表 + 事实 + 伏笔 + 编年 ——
   数据一个不缺，但玩家问的是「这个人为什么突然对我冷淡」「我上一章答应过谁」。
   我们在回答「L3 有 12 条」。（v2.537.0 的时间轴是第一块用「先后 / 压缩」这种叙事语法说话的块。）
3. **反馈闭环缺失**。0 toast / 0 骨架 / 148 处全量重渲染 ⇒ 玩家点完不知道发生了什么，
   长操作（推演、摘要、搬运）只有「…」。
4. **不可逆操作没有护栏**。5 处 confirm 对 696 个按钮。这是最容易让玩家**丢掉存档**的一类缺陷，
   优先级高于任何视觉改良。
5. **视觉语法单一**。192 个同权重区块 + 47 个同型空态 + emoji 图标 ⇒ 页面没有「主次」，
   眼睛无处停。线性/Notion/Vercel 的做法都是「3 层以内」的视觉重量表。
6. **可发现性**。39 页无搜索、无「最近用过」、无新手路径；V27 计划里已记「333 组设置无中文索引」。

## 三、学谁、学哪一条（具体到可执行）

| 病灶 | 学谁 | 学什么（可执行的那一条） |
|---|---|---|
| 屏幕主权 | Linear 侧栏 | 默认 8 条 + 「More」折叠；分组用**细标签**不用分割线 |
| 首屏问题 | Things「Today」 | 首屏只答一个问题：「此刻最该做什么」，其余全部下钻 |
| 搜索优先 | Raycast ⌘K | 一个入口搜页签 / 设置 / 实体 / 动作，命中即执行 |
| 空态 | Notion | 空态 = 状态句 + **一个主行动按钮**（不是「尚无 X」） |
| 术语一致 | Stripe Docs | 一个概念一个词（我们现在「账本 / 账簿 / 编年史」三套并存） |
| 反馈 | Vercel 部署条 | 任何 >300ms 的操作都有进行中 / 成功 / 失败三态 |
| 数据可视化 | Excalidraw（真画布） | 关系/地图是**画布**，不是列表（`<svg>0 / <canvas>0`） |

## 四、排期（下一轮 V28 的玩家端批次，按痛感排序）

- **P0 护栏**：不可逆操作统一二次确认 + toast 反馈层。**先做这个**——它会救存档，而且不依赖任何设计决策。
- ~~P1 屏幕主权~~ **已撤回**（已有玩家模式 6 页 + 5 类分类过滤）。改为 **P1 页签搜索**：
  一个输入框按 label/id 过滤页签（开发者模式下 39 页才真的需要它）。
- ~~P2 首屏一句话~~ **已撤回**：`overview-main` 在非开发者模式下**直接渲染** `WA.panelNowPage`，
  「此刻」已在首屏。真缺口是它**之后**的六页内容语言，不是再加一张摘要卡。
- **P3 命名统一**：账本 / 账簿 / 编年史 收敛到一个词（涉及 VIS_NAMES 与 5 处文案）。
- **P4 视觉语法**：图标集（替换 emoji）、空态组件（状态句 + 行动）、区块视觉重量分三级、
  关系图/地图上真画布。

> 纪律不变：**不假装有内容**。P1/P2 只重排既有数据，不新增世界状态；
> 若某页本来没数据，就把它收进「更多」，而不是给它编一张好看的假图。
