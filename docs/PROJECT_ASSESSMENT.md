# WorldAxis 项目评估（v2.586.0 现场）

> 本文所有数字都是**当时现场跑出来的**，不是承诺。要复核任何一条，跑对应命令；
> 数字会随后续版本变化，**引用请以现场输出为准**（与 `docs/gates.md` 同一条纪律）。

## 1. 定位与体量

零依赖、单文件入口（`index.js` 2346 行）的 SillyTavern 扩展，产品面按命名空间切分为
545 个引擎 + 22 个 core + 17 个 ui + 4 个 render + 4 个 actors。

| 面 | 行数 | 文件 |
| --- | --- | --- |
| engines | 179,330 | 545 |
| tests | 219,471 | 679 |
| ui | 24,176 | 17 |
| core | 14,775 | 22 |
| tools | 18,421 | 103 |
| render | 3,001 | 4 |
| actors / compat | 1,450 / 122 | 4 / 3 |
| **产品 JS 合计** | **225,200** | 592 ns / 6,106 成员 |

规模已经超过「一个扩展」的常识区间：产品面 22.5 万行、测试面 21.9 万行，测试/产品比 ≈ 0.97。
这个比例是本仓最值得说的一件事 —— **测试不是附属品，是和产品同规模的一等公民**。

## 2. 结构与真源纪律

骨架是三张账 + 一个装载次序：

- `tests/module-registry-ledger.json`：文件 / 命名空间 / 装载期边 / 调用期引用（581 / 592 / 476 / 768）；
- `tests/dead-export-ledger.json`：死子面 2,004（其中 uiDead 6）、dataOnly 795、仅测试 581；
- `tests/ns-consumer-ledger.json`：零读 ns 55，每条带 `cls` 与**可复算命令**；
- `index.js` 的 `LOAD_ORDER` 与 `tests/run.js` 的 `LOAD` 必须同批（v2.583.0 的教训）。

本仓真正的资产不是这些引擎，而是三条**反复被验证的纪律**：

1. **不写第二份真源。** 缓存型反查表（`ITEM_INDEX`）、手敲的 `BUILD_ID`、重复登记的码面，
   三处都是同一个病的不同脸 —— 本轮又抓到一次（把名单编译成装载期索引，改表后判据与表脱节）。
2. **两向自证。** 只判一面的门禁等于没门禁：真源码破坏必须现形，原版上不得假报。
   本轮所有新判据都按这条写（加一项⇒放行 / 还原⇒必拒；下限改 0⇒放行 / 还原⇒必拒）。
3. **列出 ≠ 已修。** 「已登记缺陷」不是「已修」，所以 `ITERATION_LOG` 每轮都留**未做**段。

## 3. 门禁与回归

- 8 道主门禁 + 若干专锁；全量入口 `node tests/run.js` 走隔离器（整仓复制到 `/tmp`），
  所以「跑回归不会改工作树」是可核验的（`sourceChanged: false`）。
- 上一趟整趟：**通过 26,083 / 失败 0**（此前 12 红已按根因清零：新增 data-only 资产引发的
  四处读数副本跟位）。
- 现场（v2.611.0）：上面「26,083 / 失败 0」是 **v2.586.0 的读数**，不是当前状态。全量整趟未重跑；四把专项锁单独跑时在 HEAD 上就红，逐条见 R9（其中 `ns-adjudication-v2568` 是崩溃，不是断言失败）。
- 拒收码面 1,935 个内联码，每码有归属（见证 / 死表 52 / 基线 940），新增未分类码即红。

**代价**：整趟约 2.5 小时，单节最长 792s（`v2.82.0`，占 44.5%）。分片研究已做过：
可并行面仅 4.1%，但把该节 38 把锁按 34/4 拆开可省 56.5% 墙钟 —— **尚未落地**。

## 4. 内容层（外貌 / 穿着 / 亲密）

- 外貌：`S/A/B/C` 分级 × L1–L4 覆盖下限 × 关系加权（恋人/血亲/宿敌升一级）；
  v2.585.0 起有**子项名单**（36 项，含 L2 的私处），必盖项 = 名单前 N 项，N 取自同一张下限表；
  登记面按名单判 `unknown-item` / `missing-item`（带中文名）。
- 词表：`engines/appearance-lexicon.js`，约 190 词，**data-only**（引擎不消费，
  由专锁 C5 静态钉住；`DATA_ONLY: true` 自述）。
- 本版（v2.586.0）把**名单面接进注入面**：设置键 `planHints`（默认关），开启后
  `buildBlock()` 按 `coveragePlan(effTier).required` 输出【该写】中文清单；关闭时输出逐字不变。
- 边界：代码里**不预设**年龄、自愿、题材门槛 —— 这些属于角色设定与预设层，不在判据面。

## 6. 下一步（按性价比排序）

1. **词表进注入面**：`render/inject.js` 按 `coveragePlan` 取候选词拼第二段 ⇒ dataOnly 795→794、
   零读 ns 55→54，闭环「判据 → 提示」的最后一段。风险中等，改动集中在 render 一处。
2. **把「跟位税」工具化**：`tools/new-engine.js` 扩展出 `--data-only` 档，一条命令改完
   六处派生读数（本轮手工改的这六处，正好是它的规格说明）。
3. **分片落地**：按已测的 34/4 拆分把 `v2.82.0` 节墙钟从 792s 压到 ~345s（省 56.5%）。
4. **巨型文件拆分**：`tool-diag.js` 的表驱动部分（`tool-diag-tables.js` 已 2,503 行）继续下推。

## 7. 结论

- 工程面：**A**（判据密度、两向自证、零依赖、真源纪律都在同类项目之上）；
  扣分项集中在「单文件体量」与「跟位税」两处结构性成本。
- 可维护性：**A-**（规则清晰、注释写理由；但 22.5 万行产品面 + 21.9 万行测试已到
  「一个人读不完」的量级，靠门禁替代通读）。
- 内容面：**B+**（分级/名单/词表/穿着状态已成体系；词表尚未进提示词，
  露骨描写的行为层仍完全交给文风层）。
- 主要不确定性：真宿主两项未验收（R4），以及死子面/dataOnly 的持续归因（R5）。
