# 门禁

「九道门禁 + 几把专锁」是对**结构**的说法，不是对**数量**的承诺 —— 门禁会增会撤，
撤了要有登记（见下文「原第九道门禁，已于 v2.256.0 退役」那条）。

**所有读数都是现场跑出来的。** 具体读数不写在这句话里 —— 它们在下方的
「读数表」段落，由 `node tools/gen-gates-doc.js --write` 现场跑门禁回填。
引用任何读数请以现场输出为准，**本文正文里出现的数字都是叙述性的，不是判据**。

原则：门禁是**判据**，不是报告器。设计口径统一为「**双向自证**」：
真源码破坏 ⇒ 判据必须现形；原版上 ⇒ 判据不得假报。只判一面的门禁等于没门禁。

## 一条命令的全量入口

```bash
node tests/run.js          # 全量回归：通过数 / 失败数现场打印；最近一次收口读数见 ITERATION_LOG.md
```

它是**闭包**：`tests/` 下每个锁/门禁都必须挂进 `LOAD`，否则被「测试面可达性」判为孤儿。

> 为什么这里不写「通过 11858 / 失败 0」这种数：那句话曾写死在本文里，
> 而它只在写作那一刻为真。**把一次测量的结果刻进文档，等于给未来的人埋一个假读数。**
> 要读它，跑一次 `node tests/run.js`；要留档，写进 `ITERATION_LOG.md` 的当轮 R 条目。

这三条 **不是**「又加了三道门禁」，而是**三类此前零治理的面各补第一道判据**：
- **出站面（egress）**：用户最敏感的一问是「这个扩展会不会把我聊天里的东西发到别处」。此前全库
  唯一能回答它的是 `core/api-router.js` 里那两行 `fetch`，而**新加一行外呼八道门禁一条都不响**。
- **义务面（attribution）**：README 末行那句授权声明此前**无凭据也无判据**。现在它拆成
  一张 17 行清点表，每行的许可状态如实停在 `未核对`（**缺口读数**，不是进度条）。
- **人读面**：README 是唯一给人读的那一处，而它此前**没有任何判据**读它 —— 安装第一步指向
  不存在的 Release、版本锚点落后八个版本、读数是几小时前的，全靠人记得同步。

三条都进了 `node tools/smoke.js` 的快档（现场约 10s），故「跑得动」不是问题 ——
**这正是两档回归存在的意义**：不动体系的话，新判据会立刻退化成没人跑的摆设。

## 版本条目存在哪儿（原第九道门禁，已于 v2.256.0 退役）

本仓的版本条目按版本分段存放，**不是**「README 一份、日志一份」：

| 版本区间 | 条目在哪儿 | 为什么 |
|---|---|---|
| v2.80.0 及之后 | `ITERATION_LOG.md` 的 `### R<n>` 段（单一真源） | 迭代日志逐题记录「做了 / 为什么 / 影响范围」；README 只留摘要 |
| v2.21.0 – v2.79.0 | `README.md` 的「版本历史」节（**v2.256.0 随 README 精简已整节删除**，条目并入日志存档） | 那时还没有 R 条目 |
| v2.20.0 及更早（含 `v1.x` / `v0.9.x` / `v0.8.x` / `v0.1.x`） | `ITERATION_LOG.md` 的「版本条目存档」节 | 92 条 87KB 把「最新在前」的主区挤到 800 行之后，故追加到日志末尾 |

**这里原本有一道门禁，现在没有了 —— 如实登记，不粉饰。**
`tests/docs-archive-gate.js`（及配套锁 `-v2120`）曾在 v2.121.0–v2.255.0 之间守三件事：
README 版本历史节不得残留 ≤ v2.20.0 条目 / 存档节倒序不乱 / 两处不得有同一个版本号成为条目（交集必须为空）。
v2.256.0 的「README-SLIM」把 README 改写成面向玩家的文档、**整节删掉版本历史**，
于是这道门禁要守的第一、第三面**失去了对象**，它与另外 5 个 README 治理门禁一并整套退役
（`git log --oneline --diff-filter=D -- tests/docs-archive-gate.js` 可查那条删除提交）。

退役后这一面**不再有判据**，只剩三条人工事实：
① 存档节在 `ITERATION_LOG.md` 里，首条 v2.20.0、末条 v0.1.0（倒序）；
② README 里已无版本历史节，故「两份真源」这个病**结构上不可能复发**——不是被守住了，是那个位置没有第二份了；
③ v2.80.0 之后的新条目只进 `ITERATION_LOG.md`，由 `tests/docs-archive-gate*` 的继任者
`tests/readme-slim-v2256.js` 的 A 段（退役面登记）咬着「这些文件真的不在了、也没有悬挂引用」。

> 为什么把退役写进门禁文档，而不是删掉这一节：**读文档的人需要知道这里曾经有一道判据、
> 为什么它没了、以及现在靠什么兜着。** 直接删掉会让人以为这一面从来没人管过。
> 判据的价值一半在「它拦住什么」，另一半在「它为什么被撤」。本条即后者。

**三条边界（原门禁的口径，留存备查）**：① 条目只认**行首**的闭合版本标记（`- **vX.Y.Z**` 或 `<b>vX.Y.Z</b>`），
正文里提到版本号**不算**条目；② 同号异代合法 —— `v0.9.0` / `v0.8.0` 各有两个同名条目，
是两代不同的记录，**不是重复条目，勿合并**（所以倒序判据取「无上升对」而不是「严格降序」）；
③ 该门禁只覆盖这两份文件，只读不修。

## 什么时候会用到它们

- **改产品代码后**：必跑 `node tests/run.js`。其它门禁大多已被它包住，但改导出面时 `export-contract` 会单独给出增删清单。
- **加了新模块**：`module-registry-gate`（登记）+ `inventory`（悬空）+ `LOAD_ORDER`（次序）三处都要动。
- **加了新拒收码**：`reject-code-gate` 要求每个码落进「见证 / 死表 / 基线」三类之一 —— 正解是补**可执行见证**，不是删码。
- **改 UI**：`tests/run.js` 全绿不等于浏览器里能跑（UI 层在无头环境不装载，归入「需浏览器复核」）⇒ 必须另走冒烟或实机核验。

## 读读数时最容易犯的错

1. **把「没查出问题」当成「没问题」**：门禁的输入面窄于事实时，它会安静地全绿。修法是补判据的输入面，不是改实现去迎合判据（v2.75.0 的 69 个假孤儿就是这么来的）。
2. **只看文件计数**：大块删除/移动之后必须整仓核对，逐行比对，不能只看「文件数从 90 变 12」。
3. **判据自身的项数随环境漂**：锁里若写了 `if (x > 0) { A;A } else { A }`，项数会随墙钟在 100/101 之间抖，全量读数就不可复现。项数必须无条件恒定。
4. **静态扫描的结论当成事实**：动态留痕（如 `noteFault(out.reason)`）会让静态扫描产生整片假阳性。静态只能提假设，缺口要由运行时坐实。
