# 门禁

九道门禁 + 几把专锁。**所有读数都是现场跑出来的**；下面括号里的数字是本文写作时（v2.123.0）的实测值，
只作「大概是什么量级」参考，随时会随版本推进而变 —— 引用请以现场输出为准。

原则：门禁是**判据**，不是报告器。设计口径统一为「**双向自证**」：真源码破坏 ⇒ 判据必须现形；
原版上 ⇒ 判据不得假报。只判一面的门禁等于没门禁。

## 一条命令的全量入口

```bash
node tests/run.js          # v2.120.0：通过 11858 / 失败 0；v2.121.0 / v2.122.0 / v2.123.0 未跑全量（见 ITERATION_LOG.md 的 R109 / R110 / R111）
```

它是**闭包**：`tests/` 下每个锁/门禁都必须挂进 `LOAD`，否则被「测试面可达性」判为孤儿。

## 版本条目存在哪儿（第九道门禁为什么存在）

本仓的版本条目按版本分段存放，**不是**「README 一份、日志一份」：

| 版本区间 | 条目在哪儿 | 为什么 |
|---|---|---|
| v2.80.0 及之后 | `ITERATION_LOG.md` 的 `### R<n>` 段（单一真源） | 迭代日志逐题记录「做了 / 为什么 / 影响范围」；README 只留摘要 |
| v2.21.0 – v2.79.0 | `README.md` 的「版本历史」节 | 那时还没有 R 条目 |
| v2.20.0 及更早（含 `v1.x` / `v0.9.x` / `v0.8.x` / `v0.1.x`） | `ITERATION_LOG.md` 的「版本条目存档」节 | 92 条 87KB 把「最新在前」的主区挤到 800 行之后，故追加到日志末尾 |

`tests/docs-archive-gate.js` 判的就是**这件事不许被悄悄改回去**：

1. README「版本历史」节里不得再出现 ≤ v2.20.0 的条目（迁走了就是迁走了）；
2. 日志「版本条目存档」节存在，且首条 v2.20.0、末条 v0.1.0、**无上升对**（倒序不许乱）；
3. **核心**：同一个版本号不得在 README 与存档节两处**都成为条目** —— 交集必须为空。
   这是防「两份真源」的那一条：只要有一个版本号同时出现在两处，两处就会各自演化，
   而**没有任何判据会告诉你它们已经不一样**；
4. README 仍以 `---` + `License:` 收尾，导语紧随标题。

配套专锁 `tests/docs-archive-gate-v2120.js`：A 静态契约 · B 运行时读数 · C 纯只读不变式 ·
N 负控制（7 条，全部在 tmpdir 的**真文件副本树**上做真源码破坏、再用同一套判据重跑）。

**三条边界（如实登记）**：① 条目只认**行首**的闭合版本标记（`- **vX.Y.Z**` 或 `<b>vX.Y.Z</b>`），
正文里提到版本号**不算**条目；② 同号异代合法 —— `v0.9.0` / `v0.8.0` 各有两个同名条目，
是两代不同的记录，**不是重复条目，勿合并**（所以倒序判据取「无上升对」而不是「严格降序」）；
③ 本门禁只覆盖这两份文件，只读不修。

## 什么时候会用到它们

- **改产品代码后**：必跑 `node tests/run.js`。其它门禁大多已被它包住，但改导出面时 `export-contract` 会单独给出增删清单。
- **加了新模块**：`module-registry-gate`（登记）+ `inventory`（悬空）+ `LOAD_ORDER`（次序）三处都要动。
- **加了新拒收码**：`reject-code-gate` 要求每个码落进「见证 / 死表 / 基线」三类之一 —— 正解是补**可执行见证**，不是删码。
- **改 UI**：`tests/run.js` 全绿不等于浏览器里能跑（UI 层在无头环境不装载，归入「需浏览器复核」）⇒ 必须另走冒烟或实机核验。

## 读读数时最容易犯的错

1. **把「没查出问题」当成「没问题」**：门禁的输入面窄于事实时，它会安静地全绿。修法是补判据的输入面，不是改实现去迎合判据（v2.75.0 的 69 个假孤儿就是这么来的）。
2. **只看文件计数**：大块删除/移动之后必须整仓核对，逐行比对，不能只看「文件数从 90 变 12」。
3. **判据自身的项数随环境漂**：锁里若写了 `if (x > 0) { A;A } else { A }`，项数会随墙钟在 100/101 之间抖，全量读数就不可复现。项数必须无条件恒定。
4. **静态扫描的结论当成事实**：动态留痕（如 `noteFault(out.reason)`）会让静态扫描产生整片假阳性。静态只能提假设，缺口要由运行时坐实。
