# 隐私与网络行为

本页回答 SillyTavern 用户最敏感的一个问题：**这个扩展会不会把我聊天里的东西发到别处？**

一句话：**世界状态全部落在你本机的 `localStorage`；扩展自己不发任何请求。**
唯一的出站流量是**你自己配置的 LLM API 通道**（面板「连接」页）—— 而那不是本扩展发明的，
是酒馆本来就要走的推理通道。

## 出站行为（`node tools/net-audit.js` 现场可复算）

真代码面上（注释与字符串里的「fetch」字样不算）全仓出站点共 **2 处**，都在同一个文件：

| 文件 | 形态 | 什么时候发生 | 发什么 |
|---|---|---|---|
| `core/api-router.js` | `fetch(` | 面板「连接」页点了**拉取模型列表** | 你配的 `baseUrl + '/models'`，带 `Authorization: Bearer <你的 apiKey>` |
| `core/api-router.js` | `fetch(` | 每次走该通道推演 / 生成时 | `POST baseUrl`，body 为 `{model, messages, temperature, max_tokens, stream:false}` —— 即你在酒馆里本来就会发给这个模型的那段 messages |

两条都只在**你配了那条通道**之后发生；没配任何通道时，`apiRouter.call` 直接报「未配置」而不会联网。

**不做的事**（这些不是承诺，是判据 —— 见下）：
- 不向任何第三方服务器上报。
- 不发遥测 / 埋点 / 匿名统计。
- 不从网上拉取脚本或样式（唯一的动态 `import()` 是 `/scripts/world-info.js` ——
  SillyTavern 自己的同源模块，见下）。
- 不读、不传你的角色卡 / 世界书 / 聊天内容以外的任何本地数据。

## 宿主同源 `import()`（单独一档，不是外呼）

`engines/worldbook.js` 有一处 `import('/scripts/world-info.js')`，用途是读酒馆自己的世界书模块
（世界书蓝绿灯触发引擎要用它）。它是**同源路径**，不离开本机，所以既不进上面的出站表，
也不被藏起来 —— `net-audit` 把它单列一档报出来，读者一眼能看到它在那儿。

## 数据落在哪儿

- **世界状态 / 事件 / 势力 / 记忆 / 伏笔 / 快照**：本机 `localStorage`（`worldaxis_*` 前缀的键）。
- **API 通道配置（含 apiKey）**：同上，本机。
- **面板上的任何读数**：现场算的，不落盘。
- 导出/恢复是**你主动点**的手动动作，产物是你自己下载的 JSON 文件。

没有云端账号、没有同步服务、没有后台进程。

## 判据（谁在盯这件事）

| 命令 | 盯什么 |
|---|---|
| `node tools/net-audit.js` | 真代码面上的出站点**必须全在白名单内**；白名单里每条又必须在现场命中（腐烂即红）；出站点数低于下限即红（空集上的「全部合规」恒真） |
| `node tools/smoke.js` | 把上一条放进快档 —— 每次提交前十几秒就能跑一遍 |

白名单不是「豁免表」而是**承诺书**：新增一个出站点，必须同时改 `tools/net-audit.js` 的
`WHITELIST`（写明允许的形态与理由）与本页。改表这个动作会被 review 看见 ——
这就是把「隐私承诺」从**一句话**变成**一条可执行的判据**的全部意思。

## 边界（如实登记）

- 本页只覆盖**本扩展自己的代码**（`core/ engines/ ui/ actors/ direction/ render/ compat/ index.js`）。
  酒馆本体、你装的别的扩展、你的浏览器/网络环境各有各的出站行为，不在本页承诺内。
- 判据管的是**代码里有没有计划外的出站**，不是「发出去的内容合不合适」——
  后者取决于你在「连接」页配了谁。想完全不外发，就不要配任何 API 通道
  （那时扩展功能基本不可用，但确实一个包都不发）。
