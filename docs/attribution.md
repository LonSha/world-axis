# 缝合来源与授权状态（逐条清点）

本仓是「缝合 14 个 SillyTavern 开源世界引擎的**机制**」的独立扩展。这一页回答一个此前
**没有任何地方回答过**的问题：**这些上游的许可义务，一条一条核对过没有？**

## 先说要紧的一句（如实，不美化）

**没有核对过。** 本页建立时的现场状态是：全部上游的许可类型、是否允许派生、是否要求
保留版权声明 —— 都是 `未核对`。这是本仓的一个**真实缺口**，不是一个「待办事项」：
README 末行那句「各源项目机制参考已获原作者授权（非商业缝合）」此前**没有任何判据**，
读者唯一能做的判断是「相信作者」。

本页把这件事从「一句承诺」拆成**一张逐条可核的清点表**：每一条都写明
「缝合的是什么 / 上游在哪 / 许可核对到什么程度 / 下一步是什么」。

## 状态词表（有限，扩词须显式改判据）

| 状态 | 含义 |
|---|---|
| `未核对` | 上游仓库的 LICENSE **一个字节都没读过** —— 默认态，不许默默改成下面的词 |
| `已读许可` | 上游仓库的 LICENSE 文件读过，**版权类型已记录**（允许什么、要求什么） |
| `已声明来源` | 除上一条外，本仓已在源码注释里逐文件声明上游出处 |
| `已获授权` | 有**可指名的授权凭据**（邮件 / Issue / PR 记录），能指向一条具体记录 |

⚠ 注意分清两张**不同的**栏位：**「源码内出处声明」栏**记的是「本仓有没有在代码里写明出处」
（凭据在源码注释里，可现场 grep）；**「许可状态」栏**记的是「上游的许可义务核过没有」
（凭据在上游仓库里，本仓读不到）。两栏互不等价 —— 本仓可以「已声明出处」而同时「许可未核对」，
且**现状正是如此**。

⚠ 本页**只登记，不判决**。它判不了「这样缝合合不合法」—— 那是人的判断。
它能判的是一件机械可核的事：**表里每一行的状态词必须在词表内，且不许静默留空**
（空着会被当成「没事」，而它恰恰是「不知道」）。

## 缝合的**形态**（这一条决定义务轻重，故逐字写明）

本仓的缝合是**机制重写 + 出处声明**，不是代码搬用：

- 全部产品源码（`core/ engines/ ui/ actors/ direction/ render/ compat/ index.js`）里
  **没有任何一处上游的逐字代码**、**没有任何上游的版权头**（现场核：全库 `Copyright` /
  `MIT License` / `GNU` / `Affero` 零命中）。
- 上游名只出现在**注释里的出处声明**（例：`engines/rules.js` 头注「缝合来源：DlSNlGHT World
  —— world-engine-rules-loader.js（忠实压缩，保留全部硬约束）」）。
- 因此本仓对上游的义务**大概率**落在「保留出处声明」这一档；但**这只是推断，不是核对**
  —— 有的许可（如 AGPL）对「衍生作品」的定义比「逐字复制」宽得多。**推断不替代读 LICENSE**，
  故上表的状态词一律停在 `未核对`。

## 边界（如实登记，不假称已覆盖）

- 本页**不判定合法性**：它判的是「清点表完不完整、状态词合不合规」，不是「这样缝合对不对」。
  后者需要逐条读上游 LICENSE 并做人的判断。
- 本页**不替上游表态**：任何一条最终变成 `已获授权`，都必须指向一条**可指名的凭据**
  （邮件 / Issue / PR），不接受「记得当时说过」。
- 本页是**起点不是终点**：它的价值在于把「不知道」从隐性变成显性 —— 一张 17 行全是
  `未核对` 的表，比一句没人核的承诺诚实得多，也比一句承诺更容易被推动。
