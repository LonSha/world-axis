## 一、优化九项（OPV9）

主题：**让已经建好的能力真正落到正文里**。不是再堆审计，是把「建了但没接」的线接上、把「接了但脏」的清掉。

### OPV9-1 注入块换行污染清扫
- 现场：`agency.js:533` / `family.js:447` / `research.js:464` 三处 `return` 用了 `'\\n'`（双反斜杠），产出里带字面 `\n` 两字符，模型看到的是 `[家庭]\n甲（家庭，3人）\n乙\n共同生活单位…` 里混进 `\\n`。
- 做法：三处改为 `'\n'`；新增专项锁 `tests/v9-inject-newline-2295.js`：全仓 `return` 行扫 `\\n` 字面量，命中即红（含负向：人为写回一处须报错）。
- 验收：三处修复后 `buildBlock()` 产出不含 `\\n`；锁 0 命中；负向注入 1 处即红。

### OPV9-2 四条 owner 注入源接线
- 现场：四个 owner 的 buildBlock 无正文消费者；beatFacade 聚合 beatReport/genGate，后两者已有直接消费点，因此门面零直调不是功能缺失。
- 做法：SOURCES、默认值、显示名、模块设置键、注入分支同批增加 beatLedger/family/research/opportunity；模块开关仍默认关。保留既有 collector 深层五 owner，不把全文重复灌进 collector。
- 验收：113 源双向登记一致；真实 owner 写口建状态后进入 applyInjections；关闭单源/模块后不注入；拍账不得泄漏未来待落拍标题。

### OPV9-3 五卡容量设置补齐（撤销“启用面缺位”误报）
- 逐行核对后确认：aftermath/commission/investigation/operations/storyChoice 都已有 SC/CM/IV/AF/OP 别名 getSettings 及真实 enabled 绑定，style 已有独立设置面。不得重复增加启用开关。
- 在既有五卡增加 maxEffects/maxContracts/maxClues/maxProjects/maxPending 数值编辑，范围跟真实 registry 同步，写后读回规范值。
- 验收：Chromium 实际编辑五项后 owner 值变化；绑定盘点 100%，可访问名缺口 0。

### OPV9-4 显式托管暗流推进
- backstage 是既有暗流阶段写 owner；新增 setCurrentAdvance / advanceManagedCurrents 窄口。storylineAdvance 默认关，成功推演事务后调用 owner，世界页逐条托管与停止。
- 只允许起线→延展→成形→收束→淡出；按 evolution 真实轮号和每阶段轮数，一次最多一段；同轮重答/时钟回退不前进，推演显式改段重置基准。
- 日历 etaDays 是估算，不转成事实期限。不改 summary，不自动创造事件或收尾；advanceLast 每 current 仅一条，沿用 currents 容量站点。
- 验收：五轮单调推进、未托管不动、隐藏不泄露、同轮幂等、真实浏览器托管/停止；成功推演整链专项 7/0，覆盖真实 order20/order30 与异步结算及断线源码副本。

### OPV9-5 暗流阶段五段归一
- 现场：`STAGE_WINDOWS` 23 键缺「起线/延展/成形/收束/淡出」，现靠包含式兜底（含「展」→ 发展）。
- 做法：补五键，映射到既有五档（`etaDays` 0/1/2/4/7 对应）；兜底链保留但降为最后一级。
- 验收：五键各自 `mapWindow` 命中自身而非兜底；新增负向：传五键必须不走兜底分支。

### OPV9-6 注入预算面接产品
- 已有 incrementalCost 是耗时/脏集观测，不是 token 估算，禁止拿毫秒当 token。
- 已实施：collector 选材复用 tokensOf/volumeView，保留字符上限与整行选材；全局预算仍由 render 统一裁决，不能为每源虚构独立池。last 增补真实 token 收支。
- 验收：收紧显式选材上限后输出变小、不留半截块；记录能从真实输入和输出重算。
### OPV9-7 面板折叠惰性与隔离核验
- 原「段 ID 重复」结论撤销：真实 SECTIONS 为 15 个唯一 page:id，重复是注释中的字符串，不是表项。
- 不改变现有 page:sec 存储格式，不做无效迁移；核验关闭段体不构建、展开恢复、相邻段互不影响。
- 验收：真实表唯一、15 个调用均为函数惰性体，独立 VM 设置隔离；浏览器证据另列，不能以静态锁替代实机。

### OPV9-8 长局体积回归基线
- 现场：V8 fixture stream 在 V9 当前代码重算：8→15→20 非空、25/50 轮 3524/3532 字符；不是模型自主生成故事。
- 做法：把该读数固化为基线文件 `tests/v9-volume-baseline.json`；超过基线 120% 报警而非直接红（长局本就会长）；低于基线 50% 也报警（注入塌了）。
- 验收：基线自检脚本可重算、可对比。

### OPV9-9 空世界注入自检
- 现场：空世界只有 4 个元守卫非空，正常；但「有状态却全空」是静默故障。
- 做法：`injectCollector` 补 `diagnose()`：若 `store` 非空（有 people / currents / events）但本轮候选为 0，记 `fault: 'state-but-no-candidate'` 并在面板诊断页可见。
- 验收：构造「有 people 无 plan」世界，候选为 0 时 `diagnose` 报该 fault；空世界不报。

## 二、拓展九项（EXV9）

主题：**给玩家能看见的世界厚度**。每一项都要能落到正文或面板上，不做只存在于代码里的能力。

### EXV9-1 暗流自动推进进正文
- 依赖 OPV9-4。产出「这一拍：<暗流名> 从 <旧段> 推到 <新段>（仅阶段推进，事件待确认）」的注入块，走 `SOURCES` 新源 `storylineAdvance`。
- 边界：只报推进事实，不替玩家决定暗流走向；推进失败（无 eta / 段非法）留痕不静默。

### EXV9-2 家庭线进正文
- `family.buildBlock` 接线后补内容：真实照护责任/最近交接、公共池余额、已登记继承事件；无期限明确未登记，不编超支或待办。
- 边界：只报已确认安排，不虚构新安排；成员数、余额等数字必须可追溯到 `store.family`。

### EXV9-3 研究线进正文
- `research.buildBlock` 接线后补内容：假设 → 当前阶段 → 已耗资源 → 结果（或「未定」）。
- 边界：实验确认前结果未定；通用正文无可信查看人，私密/转让研究脱敏，public 才能展示详细成果与材料。作者 view/list 保留完整资料。

### EXV9-4 机会窗口进正文
- `opportunity.buildBlock` 接线后补内容：有时限的机会、剩余窗口、涉及人物、来源。
- 边界：窗口已过必须标「已错过」而非隐藏；不得把「可能」写成「必然」。

### EXV9-5 拍账进正文
- `beatLedger.buildBlock` 接线：当前拍号 + 拍标题 + 已落拍标记 + 两条节奏铁律。
- 边界：拍号只由引擎推进，玩家自己改的当场拒收留痕。

### EXV9-6 注入预算看板
- 面板新增一段：按源列出本轮 token 占用、被折叠条数、总量占预算比例。
- 数据源：`injectBudget.volumeView()` + `injectCollector.stat()`。

### EXV9-7 设置项检索
- 面板顶部加搜索框，明确“当前页已展开设置”：按 label/中文名/设置键过滤与高亮，不强制构建其他页面或折叠段。全局设置索引未交付，不冒充全局 70+ 全覆盖。
- 边界：纯前端过滤，不改任何设置值。

### EXV9-8 世界变化摘要
- 新增「本次成功推演区间」读口：在发出前与成功结算后比对 evolution / currents / events / family / research 的固定公开投影；独立源默认关闭，仅保留一份至多五行摘要。
- 边界：只报公开类别计数和登记更新；hidden/trace 暗流与私密研究不参与，无快照或旧轮不冒充零变化。同轮重推覆盖区间，不是任意编辑事件流，文案“本轮无变化”仅指该区间公开投影。

### EXV9-9 归档续接
- `player-archive` 的 `seedPack` 支持「续接」模式：从某份归档的末态继续开新局（保留人物关系与暗流阶段，重置回合计数）。
- 边界：从指定轮既有周期作品取末态，不读实时状态；仅人物身份/已登记关系与暗流阶段/原文，非完整存档。作者私密包跨聊天在空局预览并同事务确认，轮号归零、托管关闭。重载丢尾拒绝静默降级；不改原局；UTF-8 体积上限 524288 字节。

## 四、硬边界（贯穿全程）

1. **不跑 `tests/run.js`**：双计划全部完成前禁止。专项锁读数一律标注「专项锁」。
2. **不新建无界容器**：任何新容器必须同时在 `core/evict.js` 的 `SITES` 登记 cap。
3. **不复制状态**：新引擎只读既有 `store` 读口，不另开真源。
4. **注入源与分支必须同批增长**：只加源表不加分支 = 声明了没人消费；只加分支不加源表 = 开关点了零效果。
5. **不把静态扫描当事实**：所有「缺口」结论必须有运行时读数或源码逐行核对。
6. **不堆元工作**：审计/门禁只服务于本计划的产品面，不另起第二系统。
