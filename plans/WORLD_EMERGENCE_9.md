## 创新落在哪里

本线严格为 **WX-1～WX-9 九项**。“创新”指相对于本仓已核验能力的机制增量与组合差异，不宣称行业首创。不是把旧 IN 九个模块改名再卖一遍：旧实现有可复用基础，但“有实体、有评分、有记录”不等于人物已经在正常世界中竞争、协作、改规则或承接责任。

九项共享三个约束：世界状态仍由原业务 owner 持有；人物只能依据自己已知的信息行动；持续后果必须进入下一次真实选择。机制可按题材独立启用，不要求玩家同时打开全部十八项。正常入口复用 WP-1，时间复用 WP-3，场景表达复用 WP-8，定义导入复用 WP-9；下面的估算只计本项新增行为和专属适配，不重复计算这些基础。

## WX-1｜有限机会下的多人物竞争与转向

**玩家需求。** 世界不能永远等玩家来领取唯一的工作、工位和合作机会；其他人物应有自己的选择，但玩家没有打开自动推进时也不能被墙钟偷偷抢走机会。

**已有基础与真正增量。** `motive-arbitration` 比较单人的候选，`agency/life` 安排个人行动，委托和生产已有任务与资源。新增的是**多人针对同一有限机会提出真实意向、按题材规则分配，再为落选者产生下一步行动**，不是再写一个分数器。`ensemble` 是多模型推演仲裁，不是这一能力。[证据 E10](WORLD_PLAY_BASELINE_2026-10-24.md#e10)

**必须交付的工作包。**
1. 首批机会为委托名额、限时工位、合作席位三类，引用实际任务/工位/计划，不复制资源池；公开、定向邀请与尚未送达分别决定谁能申请。
2. NPC 在正常剧情推进中按动机、位置、时段和已知条件提交意向；玩家可申请、让出、谈条件或忽略，不以打开面板先后决定谁有资格。
3. 支持先到先得、公开轮值、委托方择人三种题材规则；确定结果后由 owner 占用真实名额/时段。竞争结束前可撤回，结束后不能让双方都拿到同一独占机会。
4. 落选者可以等候、寻找替代、转向另一目标或要求解释；失约影响后续邀请，但没有理由时不自动升级为敌意。

**完整游玩链。** 三人看见同一订单 → 两人申请、一人赶路未获知 → 委托方选中熟练者 → 落选者租另一工位做自己的任务 → 首选者延期后按原规则补位 → 下一周期邀请范围受实际履约影响。

**结项下限。** 三名 NPC 加玩家、三类机会、连续三个分配周期；至少一次落选后实际换目标、一次空缺补位。仅改变到达时机、技能或承诺之一能改变合乎规则的结果；同一份资源不能双占；存档重载保留意向和最终分配；未启用自动模式不自行抢占。人物决定和结果须能在正常场景中被相关人得知。

**依赖/边界/估算。** P1，A 包，**14–20 小时**。依赖 WP-1/3/5；先消费已有工位，WP-7 后再扩到公共服务。不是拍卖平台、全局最优分配器或玩家不可见的暗箱剧情导演。

## WX-2｜共同计划、分工版本与协调失误

**玩家需求。** “大家都同意了”不应意味着所有人都知道最新安排。共同出行、工坊协作和修复任务应允许确认、迟到、误解、改约与补救，并有真正的分工产出。

**已有基础与真正增量。** `shared-awareness` 有二阶认知与 pact，`liaison` 有消息传递阶段，`org/operations` 有共同项目；`coop` 是本地提议的权威确认层。新增的是**游戏内多人分工与版本化知情怎样决定实际执行**，不是重建多人联网、聊天或项目容器。[证据 E11](WORLD_PLAY_BASELINE_2026-10-24.md#e11)

**必须交付的工作包。**
1. 在已有项目/活动上组织角色、前置依赖、会合地、时段与贡献；首批支持共同加工、共同出行、协作维修三种固定流程，不引入通用工作流语言。
2. 邀请、修改、确认和撤回走已有消息链。确认绑定所见版本，“我知道你知道”必须源于已送达回执或共同在场，不能仅凭一段声明。
3. 每人按自己所知版本和现实可用时段行动；错过变更可以到旧地点、等待或询问，而不是直接被裁为“背叛”。关键贡献缺失不凭空完成整项工作。
4. 玩家可重新分工、等候、缩小目标、付费替补或延期；投入、已完成部分和未完成责任各自保留，后续关系反馈区分误会与明确违约。

**完整游玩链。** 三人约定共修设备 → 发起人改到次日 → 一人收到、一人在旅途中未收到 → 原日出现空等 → 解释后重新排班 → 设备完工，但多付费用与占用时段不会消失。

**结项下限。** 三种计划各至少三人；一条消息延迟、一条撤回、一条部分完成后重排；重载前后每人所知版本一致。人数齐全但关键技能缺席不能完成；双方口头确认不能越过实际时间/资源约束；手机可看自己的职责并直接回应。

**依赖/边界/估算。** P1，A 包，**14–22 小时**。依赖 WP-1/3/5，消息复用 liaison；WP-8 后增强场景呈现但不阻塞 A 包基本交互。只保留相关参与者的有限二阶认知，不展开无限“我知道你知道他知道”。

## WX-3｜有边界的人情、互惠与担保链

**玩家需求。** “上次你帮过我”应能改变下一次真实求助的条件，不只是好感加一；人情也不应成为能强制兑换任何服务的万能货币。

**已有基础与真正增量。** `mend` 已有道歉、补偿、守约与第三方担保，`org` 已有债务与共同项目，外交也有履约。新增的是**跨人物/组织、非等价且可拒绝的互惠请求，以及有限担保在实际履约中的后果**；现金债务继续归原 owner。[证据 E12](WORLD_PLAY_BASELINE_2026-10-24.md#e12)

**必须交付的工作包。**
1. 真实帮助可被当事人承认为一段关系事实；记录谁知情、帮助的范围和是否期待回报，不把每次交易自动变成人情。
2. 求助时提出具体任务、时段和条件；受助者依据能力、已有责任和关系答应、缩量、延期或拒绝。一次请求不能直接转移钱物或抽走对方工时。
3. 引介与担保限定对象、期限和最大责任；担保人只承担明确同意的部分，第三方转述不自动取得担保权，也不连锁生成无限债务。
4. 完成、部分完成、撤回和违约消费实际回执；受影响者获知后再改变后续邀请、信任与要求。共同计划可把互惠作为招募来源，而非跳过贡献结算。

**完整游玩链。** 玩家曾替工坊值班 → 之后请求借用工位 → 对方只能提供半日并请第三人担保工具 → 工具晚还 → 先补偿再重建合作，未发生的责任不被凭空追索。

**结项下限。** 四人、两个组织、三次互惠往返；含一次正当拒绝、一次有限担保、一次部分履约。不能重复领取同一回报；拒绝不自动扣钱或定罪；重载保留未完承诺；实际改变至少一次招募或服务条件。

**依赖/边界/估算。** P1，B 包，**12–18 小时**。依赖 WP-5/6、WX-2；复用 mend/org/diplomacy，不做信用评分体系、金融衍生品或泛化关系货币。

## WX-4｜可引用、可区分的社会先例与规则修订

**玩家需求。** 一次争议解决之后，下次类似事情应有可引用的理由；但不同情况不能因为几个关键词相同就被套用旧裁决。

**已有基础与真正增量。** `ruling` 已有开案、通知、裁决、执行与复审，`custom-lax` 有惯例和规则状态。新增的是**真实已结事项怎样成为适用范围有限的先例，并改变后续批准与分配**。不再建裁决引擎，也不以 `decisionId` 非空代替真实批准。[证据 E13](WORLD_PLAY_BASELINE_2026-10-24.md#e13)

**必须交付的工作包。**
1. 从已完成活动、工位分配、履约争议引用事实和裁决；声明适用组织/地点、情境条件、例外和生效时点，历史事实与“现在建议怎样做”分开。
2. 在新事项中展示可适用的少量先例；当事人可主张沿用或指出关键差异，按现有权限进行批准/修订，不能让多数闲聊自动变成法律。
3. 首批实际消费者为工位排队、共同项目分工与活动名额；已生效规则改变下一次真实分配，旧规则版本保留给进行中的事项。
4. 明确废止、例外批准与过渡期；不追溯改写已经履行的交易，不把一个地区的规则无声扩大到全世界。

**完整游玩链。** 一次抢占工位引发争议 → 处理后提出轮值规则 → 有权限者确认 → 下一轮排班真正按轮值分配 → 紧急维修申请例外 → 例外理由进入后续可引用记录。

**结项下限。** 两个组织、两种规则、三次连续事项；一次适用、一次关键差异拒用、一次版本修订。必须观察到真实分配改变；无权限者提议不直接生效；进行中事项重载后仍按原版本处理；两地可以合法保留不同规则。

**依赖/边界/估算。** P1，B 包，**12–18 小时**。依赖 WP-3/7、WX-1/2；复用 ruling/custom-lax/inst。仅游戏内离散规则，不做现实司法预测或任意自然语言规则执行器。

## WX-5｜地方技术标准、兼容选择与改装投资

**玩家需求。** 不同地方做出的工具、配件和设施可以各有适用性；“学会了同名技艺”不应意味着到处通用。统一规格和保留地方做法应各有真实成本。

**已有基础与真正增量。** `tech-lineage` 已有文献、师承、实践者和变体；`confirmVariant` 主要检查调用方传来的环境条件并改为 confirmed。新增的是**由实际试制、安装和使用回执支撑的离散兼容关系，以及地方采用/改装所产生的经营选择**。[证据 E14](WORLD_PLAY_BASELINE_2026-10-24.md#e14)

**必须交付的工作包。**
1. 题材声明少量机械配件/虚构设备标准与适用工位；兼容关系有方向和版本，不以名字相似判断可安装，不提供现实制造参数。
2. 试制与适配消费 WP-4 的工单、工时和物件，结果按明确游戏规则确定；验证成功不自动复制全区域技能或永久废掉旧设备。
3. 提供继续旧工艺、购买适配件、改装工位、委托外地四种可行路线；改装期间损失产能，材料和培训投入不能被切换标签免掉。
4. 师傅、图纸与商路承担传播；离开的熟手带走的是实际能力，留下的文献不凭空生产。组织依据成本、服务条件和承诺决定是否采用。

**完整游玩链。** 外地订单要求新规格 → 本地工位不兼容 → 先外包一单 → 培训并改装 → 新单成本下降但老单暂时只能转交邻镇 → 两地形成互补而不是整图一键升级。

**结项下限。** 两地、两类非生物机械/虚构工艺、至少三种兼容关系；至少两条选择路线完成真实订单，兼容与不兼容产生不同成本/工期。更换版本不能免费回收投入；存档恢复保留改装进度；关闭本机制保留原有普通配方语义。

**依赖/边界/估算。** P2，C 包，**14–22 小时**。依赖 WP-4/7、WX-2/4；不重做知识系统，不做连续物理仿真、现实科学实验或全局自动技术树。

## WX-6｜会按周期重来的集市、轮值与地方活动

**玩家需求。** 地方应有值得提前准备和按时返回的生活节奏；错过一次集市、轮值会或展示会，会影响订单与关系，却不应让故事永久断路。

**已有基础与真正增量。** `activity` 已有筹备、报名、角色、轮次、奖励、改期和取消，不能把“举办活动”再算新功能。新增的是**可续期的活动系列、跨期准备、场地/商路约束，以及结果反馈到下一期**。[证据 E15](WORLD_PLAY_BASELINE_2026-10-24.md#e15)

**必须交付的工作包。**
1. 活动系列定义频率、地点、角色与准备窗口；每期拥有独立 activity 身份和原 owner 状态，不复制上期报名或未兑现奖励。
2. 首批为地方集市和工艺展示/轮值会：商贩备货运输、参与者请假赶路、主办方准备场地与服务，均消费真实库存和时段。
3. 到场与履行影响订单、信息接触和下一期邀请；交易仍走 economy/commission，展示本身不自动制造技能或奖品。
4. 道路中断、容量不足和主办缺席触发缩办、迁址、延期或取消；已经花费的准备成本与未完成委托继续存在，不能每次延期复制一套活动。

**完整游玩链。** 为三日后的集市赶订单 → 途中改线晚到 → 第一日摊位已满 → 接受次日轮值 → 认识外地工匠并预订下期货物 → 下期场地维修，选择迁址继续履约。

**结项下限。** 两种系列各运行三期、三个地点、两次变故；至少一项跨期订单、一次报名不等于到场、一次取消后的真实退款/未履约处理。重载不重复生成下一期；活动关闭不继续扣费；手机可以看准备事项而非只看日期。

**依赖/边界/估算。** P1，B 包，**12–18 小时**。依赖 WP-3/4/7/8、WX-1/2；WX-4 规则是可选增强，不构成硬依赖。不是再做日历或庆典皮肤包。

## WX-7｜多版本社会记忆与可被争论的地方身份

**玩家需求。** 同一件旧事，不同群体可能记住不同部分；这些版本应影响未来合作与活动，而不是历史列表换一种摘要。

**已有基础与真正增量。** `chronicle/sediment/pmem/opinion/rumor` 已有事件、痕迹、记忆和舆论，`social-legacy.witnessAccount` 已可记不同见证。新增的是**群体如何经真实传播采纳某种解释、保持分歧，并在后续行动中消费该解释**；不复制第二套事件真相。[证据 E16](WORLD_PLAY_BASELINE_2026-10-24.md#e16)

**必须交付的工作包。**
1. 解释引用原事件与具体主张，区分亲历、转述和公共纪念；支持赞誉、误解、争议三类有限立场，不通过模型润色悄悄改变事实。
2. 群体采纳需要传播或共同活动；未到达的人不知道，知道也可以不接受。更正消息只修改相关主张，不把全世界意见同时清零。
3. 记忆影响后续邀请、互助条件、公共活动主题与先例讨论；玩家可提供见证、公开澄清、保留分歧或不参与，不能靠点按钮强制所有人赞同。
4. 长期只保留相关主张与来源引用；过时传闻可淡出，但未解决争议与正在影响事项的版本不被任意挤掉。

**完整游玩链。** 两组人对一次停工各执一词 → 传闻让某工匠错过邀请 → 当事人通过展示会澄清一部分 → 一组改变合作条件，另一组仍因不同经历保留意见 → 后续事件继续修正地方印象。

**结项下限。** 两个群体、同一事件三种叙述、两次传播与一次更正；至少改变一次真实邀请或互助条件。事实事件不被投票改写，未收消息者不跳变；重载后仍可定位来源；不把全知争议清单注入每个人的 prompt。

**依赖/边界/估算。** P2，C 包，**12–18 小时**。依赖 WP-5/8、WX-3/4/6；来源已丢失时明示不可核，不捏造证据。不是舆论操纵系统、另一套长期记忆插件或无限人物心理模拟。

## WX-8｜多方承继、退出与未完项目的再组织

**玩家需求。** 一个重要成员离开后，工具、岗位、债务、关系和未完项目不应自动打包给一个人；愿意接班的人也可能只愿意承担部分责任。

**已有基础与真正增量。** `social-legacy.acceptLegacy` 已能记录接受者和范围，`inst` 有任职继任，`gear` 有物件转交，`family` 有资产处理。新增的是**多方提案与明确接受如何分别驱动原 owner 的实际交接，并在无法达成时继续游戏**，不是创造另一个资产账本。[证据 E17](WORLD_PLAY_BASELINE_2026-10-24.md#e17)

**必须交付的工作包。**
1. 对明确离场、退出或移交事件，列出可交接的物件、职位、项目、合同责任和使用权限；知识成果不等于他人技能，秘密也不自动广播。
2. 至少两名候选可接受不同范围、提出条件或拒绝；既有所有者/组织权限决定谁有权交接，社会期望不能直接没收物件。
3. 转交由各 owner 执行，区分已交接、待对方确认、争议和暂时无人承担；不能只改 legacy 状态而没有实体变化，也不能重复接受复制资产。
4. 项目可拆分、延期、临时托管或关闭；退出者先前已支付的成本与继任者新承担的义务分开记录，关系变化依赖实际获知。

**完整游玩链。** 老工匠迁居 → 一人愿接工具、一人愿接订单但不接旧债 → 与组织商定托管工位 → 补培训后继续生产 → 未接部分公开求助或关闭，世界留下明确后果。

**结项下限。** 三名候选、两个组织、五类交接对象；含拒绝、部分接受、权限不足、多人争同一物件与一次交接中重载。实际核对物件持有人、任职、项目承担者和付款义务；没有继任者也能继续推进世界。WP-6 的共同体内部份额结算不在此重算。

**依赖/边界/估算。** P2，C 包，**14–22 小时**。依赖 WP-4/6、WX-2/3/4；复用 social-legacy/inst/gear/org/commission。不是现实遗产法律工具，也不要求引入生命周期或生理模型。

## WX-9｜由投资与合作积累出的地方发展路径

**玩家需求。** 长期经营之后，两个起点相近的地方应能走向不同生活方式：一个集中共享工位，一个保留分散协作；差别要能影响下一单、下一次迁址和下一次共同决定。

**已有基础与真正增量。** `phase-transition` 已有阶段评估和进入记录，但固定标签、地区取数与 coverage 语义不能证明地方已经改变。新增的是**持续选择带来的真实投资、方法、服务与规则组合，以及转换路径的具体代价**。阶段名只总结结果，不能成为超越所有 owner 的总开关。[证据 E18](WORLD_PLAY_BASELINE_2026-10-24.md#e18)

**必须交付的工作包。**
1. 以两地三种可并存的布局为首发：分散工坊、共享服务中心、商路协作节点。使用各 owner 的实际地区数据，未启用/未知不按零或满覆盖猜测。
2. 地方压力来自真实等待、维护、订单和出行成本；玩家与组织提出建设、规则调整、培训或外包组合，通过已有项目与批准路径执行。
3. 持续兑现后才形成新的机会和成本结构；短期波动不换时代，回退要处理闲置设施、已有合同和培训投入，不能把过去消耗的钱物吐回来。
4. 对同一初始局运行两条真实选择路线，展示下一次机会、经营与协作差异；历史解释链接已完成事项，模型不能仅凭“繁荣了”直接改阶段或资源。

**完整游玩链。** 工位长期拥堵 → 一地筹资建共享站，另一地扶持分散加工 → 前者集中效率高但维护影响面大，后者运送多但替代空间大 → 相同普通故障下选择不同补救 → 下一期活动与接单结构真实分化。

**结项下限。** 两地、三种布局、至少三十个剧情回合；两条投资路线完成且在同类事件下有不同真实结果。含一次转型失败、一次代价明确的调整、一次重载续玩；不能只断言 phaseId 不同。至少一套 WP-9 蓝图能够从新局进入该流程。

**依赖/边界/估算。** P2，C 包，**16–24 小时**。依赖 WP-3/4/7/8/9、WX-4/5/6/8；WX-7 的记忆反馈可增强但不是硬前置。这里只做游戏内机械、商业与社会选择，不做现实历史预测、生态或生命科学研究，不引入全图社会模拟器。

## 本线完成标准

本线初始估算 **120–182 小时**；与优化线共 **214–322 小时**的净工程工作量。数字是排程假设，不是已经消耗的时间，也不是三天内完成承诺；共享工作归属与缓冲见[排程](WORLD_PLAY_BASELINE_2026-10-24.md#schedule)。

每项须同时留下正常入口、真实业务变化、相关人物获知、替代路径、持续后果和重载续玩证据。评分表、标签、独立 API 或新增叙事段落都不能单独结项。先交付三个完整大更新包，再做范围内精修；不把十八项拆成十八个“增加一个对象就发布”的微版本。
