## 九项优化

### O1 真实 SillyTavern 宿主验收矩阵

- **优先级**：P0。这是当前唯一"做完了但没法证明"的整类缺口。
- **现状**：TX1–TX9 九项的进度表末列**全部**写着"真实宿主面板未验"；TP3 页面恢复入口已装但"真机 bfcache 与后台节流行为未验"；TP7"真实宿主存储压力未验"；SP6 的面板控件只有 mini-DOM 锁。无头证据充足（九个专锁 + 九个冒烟脚本），但 mini-DOM 不覆盖宿主事件、页面前后台与新聊天流程。
- **实施范围**：为每个已交付模块定义四条路径 —— 成功、拒收、重载、重复 —— 在真实 SillyTavern 里逐条跑。复用仓内已有的 UI 实机通道（`tests/ui-live.js` / `tests/ui-live-v2137.js`，含第四条驱动 `builtin-cdp@node-websocket`，Node 自带 WebSocket 直连 CDP，零依赖），把它从"通道可用性验证"升级为"模块路径验证"。每条路径保存四类证据：交互序列、控制台输出、操作后最终状态、重载后状态。
- **边界**：宿主证据缺失就如实保留"待验收"，不用无头全绿顶替；不为取证据而改动产品行为（改行为属另一项）。桌面与手机至少各覆盖一组关键路径。
- **验收**：每个模块至少一条完整玩家路径在真实宿主走通并留证；每个模块至少一条拒收路径留证；重载后状态与操作后状态一致可复读。四栏表（源码 / 无头 / 宿主 / 玩家）中后两栏不再全空。

### O2 跨 TX 模块原子提交与联动回归

- **优先级**：P0。九个新模块各自事务，跨模块链没有统一候选。
- **现状**：`core/commit.js` 已有九个成员（`opKey` / `begin` / `commit` / `defer` / `flush` / `retryEffects` / `settle` / `replay` / `stat`），但真实消费方只有三处：`engines/backstage.js`（begin/commit/defer/flush/retryEffects）、`engines/coop.js`（settle/replay）、`engines/story-choice.js`（begin/commit/flush），`engines/tool-diag.js` 只读 `stat`。TX1 外交、TX2 行动、TX3 货运、TX6 委托、TX8 地点效果、TX9 运营**全部**走各自 `store.transact`。
- **实施范围**：定义五条固定跨模块场景链，每条要求至少两个引擎在**同一候选草稿**内结算，例如：外交签约 → 商路可用性变化 → 货运改道 → 委托核验；地点效果登记 → 运输受阻 → 委托超期 → 关系反馈；组织批准 → 预算拨付 → 项目执行 → 条约履约。链内共用候选与执行上下文；不可同草稿执行的公开写口不得嵌套调用。
- **边界**：不默认撤销已确立的世界事实；需要逆操作时只在已有撤销协议可证明的范围内处理。不把 `commit` 变成所有写口的强制外壳 —— 单模块单事务仍走原路径，只有跨模块链才要求候选。
- **验收**：链中第二步抛错时世界不半写；同 `opId` 资源只变一次；提交后通知失败可单独重试且不重复奖惩；重放同楼层、换滑动、刷新后重复执行结果明确。每条链配一个专锁，含真源码破坏两向自证。

### O3 手机端与长局性能基线

- **优先级**：P0。TP6 至今"未开始（需现场基线）"，是整条优化线里唯一从未动过的项。
- **现状**：基础件已交付 —— `engines/perf-ledger.js`（198 行）滚动窗口台账、`engines/perf-trace.js`、`engines/storage-forecast.js`（150 行）、面板计时与惰性渲染。缺的是真实手机存档上的三档实测。
- **实施范围**：选小局、代表性长局、容量边缘三档存档，记录生成前后、事务复制 / 序列化、生态证据校验、面板打开与切页的 p50 / p95、最长阻塞与写盘次数。按实测前两大耗时来源做增量重算、缓存读集或有界分片；先冻结宿主预算表，再评价优化收益。
- **边界**：不能用缓存跳过 O1 / O2 的提交复核，也不能为减少复制改成无提示部分提交；第三方测量库只临时放 `/tmp`，不进零依赖仓库。未采到基线时保持"待验收"，不报百分比收益。
- **验收**：同样存档、同样操作、同样世界结果作前后对照；选中热点的复制次数、写盘次数或阻塞时间有可解释下降；p95 满足已冻结的宿主预算；失败隔离与视角过滤不退化；手机触屏滚动与前后台恢复有实机数据。

### O4 存储压力、迁移与恢复实机验证

- **优先级**：P1。TP7 的源码与无头两栏已齐，实机压力栏空着，而 TX 线新增了五类持久记录。
- **现状**：`__BOUNDED_CAPS` 在 `core/store.js:1350`，`core/evict.js` 有 SITES 登记，`storage-forecast` 已接入。TX1 的条约与态度、TX3 的在途货物、TX6 的委托阶段与托管、TX7 的案件与证据引用、TX9 的项目与债务，都是新增的不可丢记录。
- **实施范围**：区分可回收历史与不可丢义务（在途消息、货物、待履约条款、回执去重索引）；容量满时采用暂停受理或明确归档；用 `storage-forecast` 提前提示并核验 cap 设置与实际写者一致。格式迁移走版本、预检、候选转换与失败保留原存档。
- **边界**：对未完成义务不静默挤出，对关联记录不独立删除成悬空引用；历史截断明确标注覆盖范围；存储配额与权限失败按 `store` 合同返回，不猜测宿主自动保存成功。
- **验收**：填满各新增容器、调小 cap、模拟配额不足与写盘抛错、旧版迁移、损坏输入、重载与恢复；未完成货物 / 条约 / 义务不失踪；余额不被失败迁移改变；失败后原存档仍可读取；新增容器登记完整且策略被真实写者消费。

### O5 玩家可读的"世界健康中心"

- **优先级**：P1。诊断能力极强但面向维护者，玩家侧仍是十七页原始读数。
- **现状**：`engines/tool-diag.js` 4327 行，为每个模块提供 `secXxx()` 诊断节与 `UI_BINDINGS`；`ui/panel.js` 727KB / 17 页签 / 约 130 个控件前缀族。拒收码有 DEAD 表与见证（`tests/reject-code-coverage.js`），但**没有任何一个面向玩家的聚合视图**回答"我现在有什么没做完 / 卡住了 / 快满了"。
- **实施范围**：统一"待办 / 阻塞 / 水位"三栏摘要 —— 待办来自各模块 `pending()`（story-choice / commission / operations / aftermath / agency 等），阻塞来自拒收码与故障计数（`stat().faults` / `lastReason`），水位来自 `__BOUNDED_CAPS` 与 `storage-forecast`。每条摘要可下钻到对应模块、拒收码与设置控件。
- **边界**：只做聚合与下钻，不新增第二套状态；不替代各模块自己的确认语义；不把维护者诊断（原始统计、内部路径）搬进玩家面。
- **验收**：一屏内能回答"现在有什么没做完 / 卡住了 / 快满了"；每条摘要点进去落在正确的模块区块与设置项；空态与"全部正常"可区分；关闭某模块后其待办不再出现。

### O6 测试套件分层与全量回归加速

- **优先级**：P1。全量回归是当前唯一的验收入口，也是最大的单次成本。
- **现状**：`tests/run.js` 21806 行 / 1.73MB / 223 个 section，隔离运行器硬超时 1500000ms；v2.131.0 实测整趟 439.0s（节内合计 435.04s），196 节里只有 2 节超 60s —— **问题是总时长，不是单节**。`tools/slow-sections.js` 已能归集慢节。
- **实施范围**：提供分层入口（快 / 中 / 全），用现有 section 名与专锁文件做分层依据；慢节显式标注并可选跳过；输出落盘以避免大输出 PIPE 死锁（子进程输出直写文件、不走管道）。
- **边界**：分层不得改变全量判据；跳过只允许显式声明并记录在读数里；全量入口仍是 `node tests/run.js`，分层入口是它的真子集而非替代品。
- **验收**：分层入口跑出的通过集是全量通过集的真子集且可复核；跳过项在输出里逐条列名；分层不得让任何既红项变绿；全量入口的读数与分层前逐字一致。

- **优先级**：P0。TX7 秘密揭示、TX1 签约、TX6 委托条件都在制造"玩家不可知"数据。
- **现状**：`engines/perspective-lock.js`（451 行）已有观测过滤，`engines/inject-value.js`（403 行）有引用率统计。但导出与剪贴板通道是另一回事：`ui/panel.js` 里 `navigator.clipboard.writeText` 至少七处（日志复制、错误报告、审计报告、导出块等），另有快照导出 `wa-snap-dl` 与 `store.exportAuditReport`。
- **实施范围**：按六条通道逐条验"玩家不可知数据不得出现" —— prompt、DOM、ARIA、剪贴板、导出文件、日志。把"玩家已知 / 全知诊断"的切换做成显式权限，而不是靠调用方自觉。
- **边界**：不凭结构引用率裁定文学质量或真相；不自动把未验证传闻写成事实；全知数据在玩家视角下**不进 DOM**（不是 CSS 隐藏）；需要全知诊断时显式切换权限。
- **验收**：未揭示的秘密、未到货的货物、未签约的条款、未确认的调查不出现在 DOM、ARIA、剪贴板、导出文件、日志与注入中；全知视角可合法查看同一数据；关闭模块与预算降档的行为与设置一致；每条通道配一个负向断言（构造玩家不可知数据，断言六条通道都不含它）。

## 实施顺序

| 批次 | 范围 | 结束时玩家/维护者可见成果 |
|---|---|---|
| 第一批（闭合当前产品） | O1 + O2 + O9 | 九个已交付模块在真实宿主走通并可留证；跨模块链不半写；玩家不可知数据不泄漏 |
| 第二批（解决长期使用） | O3 + O4 + O5 | 手机长局有基线有预算；存储压力与迁移实机可恢复；玩家一屏看到待办/阻塞/水位 |
| 第三批（降低维护成本） | O6 + O7 + O8 | 回归可分层、计划不再反向误导、导出面有消费者登记 |

O1 / O2 / O9 从第一批起持续维护（新增模块即纳入），第三批是治理收口，不是把证据工作全部拖到最后。
