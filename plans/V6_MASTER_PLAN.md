## 立项现场：四条硬读数

V5 双九项已全部交付（`v2.239.0`–`v2.244.0`），十九项机制真实落地。本轮实测暴露的
不是「机制还不够」，而是「机制做了、玩家碰不到」：

| 读数 | 实测值 | 探针 |
|---|---|---|
| 带 `enabled` 开关的引擎 | **179** 个 | `p_defaults.js` |
| 其中默认开启 | **18** 个 | 同上 |
| 其中默认关闭 | **161** 个 | 同上 |
| 关闭但**有 `buildBlock`**（真会进注入面的世界机制） | **95** 个 | `p_off_classify.js` |
| 注入 `SOURCES` 源数 | **107**（表齐全，`unranked=0`） | `p_inject_default.js` |
| 空世界下产出非空的源 | **4** 个：`livingWorld` / `healthPreflight` / `antiOmniscience` / `outputGuard` | 同上 |
| 长局填充后注入用量 | **1039 / 2400 token（43%）** | `p_budget2.js` |
| 95 个关闭引擎全开后的稳定性 | `setSettings` 抛 **0** / `buildBlock` 抛 **0** | `p_allon.js` |

**结论**：本仓八万行机制与 V5 十九项交付物，绝大多数躺在 `enabled:false` 后面。
玩家装好插件、填好 API、开着自动推演，拿到的注入面是 `4/107` —— 这不是设计上的克制，
是**能力默认隐身**。V6 的主题因此定为：**把已经做完的世界，真正交到玩家手上**。

另一条同等重要的读数：预算只用到 43%，说明**注入面没饱和**。V6 的优化不得靠
「调低预算 / 删源」来做，那是砍能力换指标。

### v2.260.0 实测修正（OPV6-5）

- **落盘真相**：`worldaxis_inject_visibility_v1` 出厂原值 **null**（玩家从未配置），107 源全走 `__REG.def`；def 中默认 false 仅 3 个（`echoes` / `opinion` / `style`）。面分布 `{unavailable:24, vis-off:3, mod-off:74, on:6}`。
- **「配过」的判据只能是总线读源**：`read()` 必 `applyDefaults` 补满 107 子键、返回恒非空，拿返回值判「有没有配过」会**恒为 true**（出厂态被报成玩家配过）。`stats.lastRead` 又是**全局单槽**，被判据引用会被后续任何一次读覆盖 ⇒ 正解走 `readEx()` 契约口（内部 read 后立刻封装来源，抗插队）。
- **`moduleEnabled` 是三态**（true/false/**null**）：null = 该源无模块级总开关、由 store 直供。默认关的源必须逐个落进 `silent` / `doubleOff` / `noSwitch` 三桶，三桶相加须等于 `defaultOff` 长度；只写两支会让第三态源**人间蒸发**。
- **与 faceAudit 分列不合并**：那面是四态封闭集（`on/vis-off/mod-off/unavailable`），`tests/switch-matrix-v2910.js` 有全景负控制；本面在顶层 `visibilityDefault()` 单列，不塞第五态。

### v2.261.0 实测修正（OPV6-6）

实施期用 `tools/v6probes/p_budget2.js` 取了现场读数，计划原文的「把 `-1 自动` 的口径改为用量驱动」
按实测改成了更小心的三件事——原文那条若照做会把「额度」与「用量」两个概念搅在一起：

1. **余量先要能读出来**（原文「如实报余量」是真需求）。实测 `plan()` 返回的 `remain` 字段
   早就存在，但**三处消费面全都没读它**：`summaryText` 只有 `注入 500/2400t`，诊断包只有
   `used`/`cap` 两个裸数，面板同形。本版新增 `budgetView()` 作为唯一判据口，三面共用。
2. **`-1 自动` 与「从未配置」必须分得开**（比原文更严）：两者在旧读数上都报 `source:"default"`
   （`autoBudget()` 量不到上下文窗口时返回的就是它）。玩家按 `-1` 的语义以为额度随上下文长，
   实际恒 `DEFAULT_BUDGET`，界面上无处告诉他——同一类假绿在本项目第三次出现。
   本版补 `mode`（auto / auto-noctx / manual / off）与 `requested`，`source` 语义逐字不变。
3. **「档位建议」只出建议、不写配置**：`advice` 只在闲置过半且真裁过项时给出，且逐字写明
   「也可以不动——空闲额度没有代价」。预算档位的写入口仍在玩家手里（`backstage.setSettings`），
   本版零写路径。

**不做清单**（明确不做，避免「为了一个读数改掉裁决」）：
· 不把自动档改成按用量自适应（那会让同一份世界在不同轮次拿到不同额度，复现性变差）；
· 不自动收紧预算（计划原文即「不做把预算调小」）；
· 不动 `overBudget` 的既有语义（它是裁决结果；`saturated` 是另一件事，两者并列不互相冒名）。

**当时下一批**（已于 `v2.262.0` 交付）：OPV6-7（设置页收敛：从 12 个分区到玩家动线）。

### v2.262.0 实测修正（OPV6-7）

**现场立据**（`tools/v6probes/p_lane.js`）：设置页 12 个 `wa-sec` 全按引擎分区摆，
一屏接一屏、零导航。玩家要改「一次推演多深」得在「世界推演设置」与「叙事工艺」之间来回找。
实测读数：HTML 17572 字节、`sec 总数 = 12`、`无 lane 的 wa-sec = 0`、导航按钮 6 个。

**交付采用「零破坏方案」**——计划原文说「按玩家动线重排」，实施时判定**不移动任何控件**：
重排会动 40 余个既有 id 与一整套 `bind()` 绑定（档位按钮 / 净化规则 / 区域 / 舆情 / 演化 /
随机事件 / 天气联动），风险面远大于收益。改为在原有结构上**加一层动线导航**：

| 改动 | 位置 | 说明 |
|---|---|---|
| `data-wa-lane` / `data-wa-sec` | 15 处 `wa-sec` | 源码 15 处 / 运行时 12 段，差 3 是分支块缺席态备用标注 |
| `LANES` + `laneNavHtml()` | 导航条 | 六个按钮 id **逐行字面量**（门禁 H2 从字面量采集） |
| `laneApply(rootEl, lane)` | 分组函数 | 按「sec 到下一个 sec 之前」的兄弟节点显隐，返回真读数 |
| `__laneSel` | 模块级状态 | 保住重绘后的选中态 |
| `laneSayNote(lane, r)` | 说明条 | 把「这一路几段、都叫什么」写入 `#wa-lane-note` |

**为什么不用 CSS `~` 分组**：`wa-sec` 与内容不是父子关系，`~` 无法「止于下一个 sec」，
会隐藏后续全部 —— 正是本仓反复付过价的「靠顺序活着的判据」。改 JS 遍历、每次切换重算。

**实施期抓到三处缺陷（全部修掉并写成判据）**：

① **探针切片偏移**：`x.slice(15, -1)` 应为 14，lane 名被截断成 `{"ower":2,"i":1,"orld":5}`。
探针自身缺陷，但会掩盖真实分布读数 —— 修后分布正确 `{power:2, ui:1, world:5, people:1, story:3}`。

② **渲染残留 2 处 markdown `**`**：来源是 `title` 属性里的 `**推导值**`。HTML 属性不吃 markdown，
tooltip 会原样露出星号。这是既有缺陷（非本版引入），一并修掉；专锁 C10 断言渲染结果零 `**`。

③ **未知 lane 把整页藏光**（`shown=0 hidden=3`）：设置页藏光是玩家**完全无法自救**的失败形态
（导航条自己也在页里，一起藏了就再也点不回来）。本版加兜底：未知动线一律回落「全部」并标
`fallback:true`；专锁 G1~G8 覆盖空串 / `undefined` / 拼错三种形态。

**另一处真缺陷（门禁抓到，非本版引入）**：一度新增 `uiSettings.lanes()` 让专锁读动线表，
`dead-export-gate` 当场判红「`+ uiSettings.lanes [test-only]` 仅测试引用（产品代码零引用）」。
按本仓纪律（产品不为「让判据看得见」多长一个镜像面）撤除该导出，判据改读运行时真值：
渲染出的导航按钮 `data-wa-lane-go` + `laneApply` 的读数。冻结面 `uiDead` 由 6 降到 5。

**专锁**：`tests/settings-lanes-v2262.js`，**178 通过 / 0 失败**，A~R 十八节（含 R 段说明条活口）
与 N1~N6 六组负控制（每条「真源码破坏 → 装破坏副本 → 重跑同款判据」+ 正版双向自证）。
六条负控制的现场读数：N1 破坏兄弟遍历 ⇒ 子控件不被显示；N2 破坏 lane 归属 ⇒ story 段数变少；
N3 破坏兜底 ⇒ `shown=0` 空屏；N4 破坏「全部」分支 ⇒ 切回仍残留 `none`；N5 按钮 id 拼接 ⇒
静态采集不到而运行时仍活着（守卫变僵尸）；N6 破坏重绘恢复 ⇒ 说明条与实际分组脱节。

实际结论句的**措辞真源**落在 `engines/health-preflight.js`，而不是面板或 tool-diag。

**实测抓到的三处问题**：
① `dormantWorld` 同名不同算法 —— `capabilityTier.view().dormant` 含 `no-builder`，

② thin 判据与门槛②**重复真源**（都按 0.5 判）—— 同一条规则算两遍，阈值必然漂移。
   去重为只认 `degraded > 0`，并加反向判据「体内不许再出现比例算式」。
③ 探针首版 C/D 面是**空壳**（`withThree()` 从未被调用、D 面只打一句「由专锁验」）。
   空壳比没有更坏：它让「四态未必真走得到」看不见。重写为真驱动 —— 换掉三个**函数外**
   依赖（capabilityTier / injectBudget / render），四态各走一遍并实测全覆盖。

**零破坏不适用本项**：本项是纯增量（新函数 + 新块 + 诊断新子节），一个既有控件都没动。

## 纪律（逐条来自本仓已付价的教训）

1. **先立据后动手**：每项开工前用仓外探针复现当前形态，修改后用同一探针证明形态已变。
2. **负控制两向自证**：真源码破坏（锚点恰中一次）→ 加载破坏副本 → 同款真判据必须现形；
   原版上同判据必须为真。负控制层内锚点字面量只准声明一次，判据不得引用锚点串。
3. **档位不是开关**：任何「一键开启」都必须逐引擎真实 `setSettings` 并复核读回，
   部分成功就是部分成功，不折成「已开启」。
4. **不新建第二套真源**：档位走 `settingsBus`；能力审计只读；日记、动线、温度计全部
   复用既有 owner 的读口，不落新容器、不碰 `store.transact` 的写面。
5. **预算不靠砍**：43% 余量是未用上的能力，处置方向是让玩家知道还剩多少，不是调低上限。
6. **版本跟随面同步**：`index.js` / `manifest.json` / `tests/run.js` 版本钉 / 台账 version /
   s3 系列白名单，一处不改即红。
7. **全量回归留足 30 分钟窗口**：`tests/isolated-runner.js` 接管后全量约 27 分钟，
   外部短超时会 SIGTERM 提前杀，误判为「只跑到 N 条断言」。
8. **大文件落盘先核验**：heredoc 长中文会被终端污染（行错位与乱码），计划与文档
   一律先写文件再 `wc -l` 核验，不信任一次写入成功。
