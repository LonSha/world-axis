# WorldAxis V12 双计划：可观测闭环与可控创作扩展

> 立项依据：V11 已完成 18/18 专项矩阵、真实 ST 交互收口与窄屏验证。V12 只承接已验证的真实缺口，不重复 V11 历史条目。

## 优化线 OPV12

- OPV12-1：统一运行时验收报告，将矩阵、宿主交互、持久化和外部模型边界汇总为机器可读报告。
- OPV12-2：优化 V11 矩阵执行成本，拆分重复装载与长任务阶段，保留正反控制敏感度。
- OPV12-3：补齐真实 ST 页面业务交互矩阵，覆盖键盘、重复挂载、弹层关闭、重绘后监听和长文本。
- OPV12-4：期刊配置回填、删除和已读状态管理，保持非权威内容边界。
- OPV12-5：补充期刊多刊并发、失败重试、初始化切换和容量淘汰的定向压力锁。
- OPV12-6：外部模型供应商适配层的可验证性：请求摘要、超时、拒绝和脱敏证据，不记录密钥。
- OPV12-7：统一错误码见证生成，避免新增功能产生未分类拒收码。
- OPV12-8：完善快照、期刊与原生聊天的跨重载一致性探针。
- OPV12-9：建立发布前定向验收清单与版本账本同步门禁。

## 拓展线 EXV12

- EXV12-1：期刊栏目与文章类型配置。
- EXV12-2：世界内专题刊、特辑和按剧情事件触发的出刊规则。
- EXV12-3：期刊阅读器分页、筛选、搜索与历史导航。
- EXV12-4：从公开世界事实生成可追溯的文章引用索引，但不升级为权威事实。
- EXV12-5：可控编辑部角色与刊物风格模板。
- EXV12-6：期刊与待办、时间线、事件日历的只读联动。
- EXV12-7：快照查看器的差异标注、折叠对照和导出增强。
- EXV12-8：真实 ST 中的可恢复导入导出与跨聊天迁移流程。
- EXV12-9：面向用户的验收诊断包，能导出脱敏状态、版本与失败原因。

## 纪律与顺序

1. 先写专锁和正反判据，再改产品代码。
2. 所有页面行为必须有真实 ST 证据；源码级和受控 API 证据不得冒充宿主验收。
3. 期刊生成继续默认关闭，外部模型调用必须明确标注受控或真实供应商边界。
4. 保持 `worldFacts`、期刊正文、快照和聊天持久化的单一真源与容量登记。
5. V12 双计划全部收口前继续禁止全量 `node tests/run.js`，只做定向专项和局部测试。
