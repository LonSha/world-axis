## 九项拓展

### Y1 拍控制中心（玩家侧拍引擎面板）

- **要解决的玩家问题**：v2.189.0 把「按拍推进」做成了四个引擎（拍回报 / 计划复验 / 拍账 / 生成闸门），
  但玩家在面板上看不到任何一样：不知道**现在卡在哪一拍**、**上一拍被判了什么**、**为什么这一拍没过去**。
  现场读数：`grep -c 'beatReport\|beatLedger\|planAudit\|genGate' ui/panel.js` = **1**（且是显示名映射）。
- **新功能**：一页「拍控制中心」：
  ① 当前拍号 + 本章已落拍数（读 `beat-ledger.current()` / `view()`，含 `overwrites` / `lastClaim`）；
  ② 上一拍判定（`beat-report` 四值 + `purpose` / `keeps` / `need` 明细）；
  ③ 四闸卡点直读（`gen-gate` 按轮记账，面对玩家说「还差几轮」而不是内部计数）；
  ④ 计划复验入口（`plan-audit`，只读，展示复验结论与依据，**不提供任何写按钮**）。
- **边界**：中心页**不写 store**（包括不「重置拍号」）；不让玩家手动改拒收判定；
  四个引擎全关时该页显示「未启用」而不是空表；数字化显示一律附「真源」提示（拍号来自引擎而非面板缓存）。
- **验收**：① 四引擎全开 / 全关 / 部分开三态下面板都不报错且不产生写入；
  ② 面板显示值 == 引擎直调值（同刻对照，由测试断言）；
  ③ 拍由引擎推进（面板不得自行 `claim()`）；④ 专锁含真源码破坏两向自证。

### Y2 章节生成工作台（把「按拍推进」做成可操作流程）

- **要解决的玩家问题**：`engines/chapters.js` 面板消费只有 **3** 处，章节事实上是个「后台概念」：
  玩家写了半天不知道第几章、本章目标是什么、还欠哪几个待补的因。
- **新功能**：一个面向章节的操作台：① 开章（目标 / 已定伏笔 / 本章约束）；② 逐拍推进
  （每拍显示「按住哪一拍 + 待补的因」，来自 `beat-report.buildBlock()` 的同一真源）；
  ③ 收章检查（未落的拍、未补的因、未回收的伏笔）；④ 章节与编年史联动（收章即入 `chronicle-view`）。
- **边界**：工作台是 **章节流程的界面**，不新增一套并行拍状态（单一真源 = `beat-ledger`）；
  不跨章合并判定；收章不得自动清理玩家数据；与 Y1 共享数据不得双写。
- **验收**：① 开章→推进→收章全链在面板可完成，且每步有重载后仍成立的读数；
  ② 中段拒绝（闸门卡、拍号不符）能显示原因与下一步；③ 与 Y1 数值同源（同一拍在两页必须相同）；
  ④ 无头测试 + 至少一组真实宿主路径。

### Y3 存档槽与分支世界

- **要解决的玩家问题**：`engines/checkpoints.js` 已有槽位与迁移（16 处面板消费），
  但玩家换存档后「想回到某一句之前重来」只能靠整档回滚；同时 `beat-ledger` 的「已落拍不可改」
  在真回档后需要被正确对待（否则要么谎报拍已落，要么报错）。
- **新功能**：① 槽位分组（自动 / 手动 / 分支）与命名；② 「从这一拍另开一世界」：复制当前世界为一个分支槽，
  分支自带世界名与父子关系；③ 分支对比视图（只读）：两世界的章/拍/关键事实差异；④ 回档后的拍账一致性提示。
- **边界**：分支世界是**独立存档**，不是同一世界的新键（不得把两世界写进一个 `stat_data`）；
  对比**只读**；容量面仍走既有 `capacity-audit` / `storage-forecast` 预算（不许绕过限额）；
  回档不得静默删账（拍账的“不可改”是拒绝覆写，不是拒绝换世界）。
- **验收**：① 建分支后原世界逐字不变（哈希对照）；② 两世界来回切换后拍账仍自洽（不串号）；
  ③ 容量超限时有明确拒绝而不是静默丢数据；④ 无头专锁 + 至少一条真实宿主的存档/重载路径。

### Y4 待办中心（把「现在等我做什么」做成一个面）

- **要解决的玩家问题**：`engines/pending-center.js` 已经把 aftermath / commission / investigation / operations
  这类挂起项做了聚合（该文件自带「模块 → 归属世界/人物」映射），但玩家没有单一入口把它们看完；
  这些挂起项散在各自模块的面板段里。
- **新功能**：单一待办页：① 按归属（世界 / 人物 / 组织）分组；② 每条显示来源模块、到期条件、
  不处理的后果（来自拒收码的恢复语义，见 U5）；③ 一键跳到来源模块（跳转，不代写）。
- **边界**：待办页**不是新的状态容器** —— 条目的唯一真源仍在各模块，本页只做读取与聚合；
  跳转不改变任何状态；聚合失败时显示部分结果并标注哪一源不可读（不假装「没有待办」）。
- **验收**：① 空 / 单源 / 多源 / 单源不可读四态都如实呈现；② 聚合结果 == 逐模块直读之和；
  ③ 与拒收恢复语义一致（不得建议「忽略即可」）；④ 聚合不产生写入（写入计数为零）。

### Y5 世界快照与整包搬运

- **要解决的玩家问题**：玩家想把一个世界（含规则 / 人物 / 地图 / 编年史 / 拍账）拿到另一台设备或另一个存档继续，
  目前只能靠整张世界书导出。全仓 `bundle` / `portable` 关键词**零命中**（本次实测）。
  `engines/world-blueprint.js` 有蓝图与导入面，但那是「用蓝图生成世界」，不是「把已有世界搬过去」。
- **新功能**：① 世界快照（单文件、可读 JSON、带 schema 版本）；
  ② 导入时的兼容检查（schema 版本差 / 缺失模块 / 命名冲突）；③ 导入预览（将要新增什么、覆盖什么、跳过什么）；
  ④ 快照与蓝图互转（蓝图是可复用的“种子”，快照是具体世界的“照片”）。
- **边界**：导入**默认不覆盖**已有键（冲突要么重命名，要么整世界另开槽）；
  版本不兼容时**拒绝导入并说明差异**，不做「尽力而为」的静默降级；不把密钥 / 宿主机密写进快照；
  快照不得包含无法复现的宿主状态（如面板展开态）。
- **验收**：① 导出→导入往返后世界关键面逐字一致（哈希对照）；② 缺失模块 / 旧 schema / 冲突键三类都有拒收或预览，
  不得静默丢字段；③ 导入大世界时有容量预检；④ 损坏文件有可读错误而不是抛异常。

### Y6 世界历史检索（跨库检索面）

- **要解决的玩家问题**：世界玩到长局后，“三个月前那个茶楼老板叫什么”“扁担巷第一次出事是哪一章”这类问题无法回答。
  现状：`engines/wb-search.js` 存在，但**全仓只有 2 个文件命中 `search`**（另一个是 `tool-diag`），
  即检索本身未成为玩家的一个“面”；`chronicle-view` 只能按时间线浏览，没有按词检索。
- **新功能**：① 统一检索入口（编年史 / 人物 / 地点 / 组织 / 规则 / 世界书条目一次查）；
  ② 结果带回溯（时间点 / 所属章节 / 来源模块）；③ 检索词的持久化（最近查询、常用过滤）；
  ④ 从结果跳到来源面（只读跳转，不代写）。
- **边界**：检索是**只读面**；不引入全文索引的持久化缓存（不靠新世界键，至少首版不把索引当世界事实）；
  结果必须标注来源（不得出现无法追溯的条目）；空结果不得被误报为“没有数据”——
  要区分「真的没有」与「源不可读」。
- **验收**：① 对同一词，检索结果集合与逐库直查的并集一致；② 大世界下检索响应可接受（走 U6 的预算）；
  ③ 源不可读时如实标出；④ 检索不产生写入。

### Y7 地图与关系可视化

- **要解决的玩家问题**：`engines/atlas.js` 已有地点 / 路线 / 关系三表与 `view`（面板 8 处消费），
  但呈现是**平面列表**；`faction-graph` / `bonds` / `opinion` 的关系数据也各自为政。
- **新功能**：① 关系图（人物—组织—地点三类节点，关系强度/方向可读）；
  ② 地理视图（路线可达性、未探索区域标记）；③ 时间轴叠加（关系随章节变化的对照）；
  ④ 图上直接提出“下一次该去哪”的建议来源说明（不代玩家决定）。
- **边界**：图是**视图**，不是新真源（节点与边一律从既有表读）；
  节点数上限与布局复杂度受 U6 的宿主预算约束（超限时降级成表格而不是卡死）；
  不隐去坏数据（无来源的边要标为孤边而不是丢弃）。
- **验收**：① 图上节点 / 边集合 == 既有表直读；② 大图不阻塞面板（在冻结预算内）；
  ③ 孤边 / 循环 / 缺节点三类异常可见；④ 视图不产生写入。

### Y8 规则包与预设扩展

- **要解决的玩家问题**：`engines/rule-pack.js` 面板消费 **29** 处、`preset.js` / `preset-world.js` / `rules.js` 均存在，
  但玩家拿到的是“一个又一个开关”，没有“成套餐 / 可分享 / 可回滚”的玩法。
- **新功能**：① 规则包（开关集 + 参数 + 说明，可导出/导入）；② 预设世界与规则包的组合（开档即定档）；
  ③ 冲突检测（两条规则互斥 / 同一参数两处写）；④ 一键回滚到上一个规则包（只回滚规则，不动世界事实）。
- **边界**：规则包只影响规则面，**不得携带世界事实**（人物 / 事件 / 地图不进规则包）；
  冲突时必须拒绝启用并指出两条规则，不做“后启用的赢”；回滚不删世界数据；
  导入的包一律做 schema 校验。
- **验收**：① 导出→导入→启用→回滚全链可复读；② 冲突包在启用前就被拒；
  ③ 回滚前后世界事实哈希不变、规则面回到目标态；④ 与 `settingsBus` 的既有读写口一致（不造旁路）。

### Y9 世界实验室（不污染正史的推演面）

- **要解决的玩家问题**：`engines/world-lab.js` 已有推演臂（面板 23 处消费），但“实验室”这件事最关键的一层
  —— **结果不回写正史** —— 没有对玩家明说，也没有在界面上被硬性保证。
- **新功能**：① 沙盒推进（在实验室里跑 N 轮，看世界会怎样）；② 结果报告（关键值变化 / 拆解成几条可解释的原因）；
  ③ 选择性采纳（把报告里的**某一条**做成真正的世界事件，走正常提交链，留下“人批过的”记录）；
  ④ 实验室与拍引擎联动（跑拍引擎的推演而不落拍。）
- **边界**：实验室内的推演**绝不回写正史**（唯一写入通道是“选择性采纳”，且必须走 U2 的统一提交）；
  推演不得占用拍号 / 不得进拍账；报告里不得出现不可追溯的来源；
  实验室关闭时零影响（注入面与旧行为逐字不变）。
- **验收**：① 推演 N 轮后世界哈希不变；② 采纳一条后世界只变一条，且可看到来源与批准点；
  ③ 推演不推进拍号（拍账前后逐字一致）；④ 专锁含真源码破坏两向自证。
