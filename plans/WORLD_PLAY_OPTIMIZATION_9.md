# WorldAxis 优化提升计划：让已有世界机制真正一起运转

状态：**待实施的产品计划，不是完成清单**。制定日期：2026-10-22。
基线：`c6ff687`，工作版本 `2.231.0`，仓库 `LonSha/world-axis`。
配套：[拓展、拓宽与创新九项](WORLD_INNOVATION_9.md)。两个方向均服务 WorldAxis，合计十八项，不另开无关项目。

## 判断与证据边界

WorldAxis 已有大量机制。当前最有价值的优化不是继续增加检查器，而是让玩家的一个行动能同时影响人物、物件、时间、组织与世界，并在下一场景里看见结果。

本计划依据定向源码阅读、真实入口/调用方检索和研究/家庭四个相关专项，不冒称完整阅读或实机验证了全仓。研究 50/0、家庭 83/0、生产 90/0、题材配方 73/0 均为专项结果；依用户要求未跑全量回归，真实宿主验收未执行。静态发现、行为证明与设计推断分别列出。

旧 `O/E`、`TP/TX`、`U/Y` 保留历史价值，但其基线与进度不代表此刻现场；特别是生成状态以测试文件存在和在 `tests/run.js` 被引用为依据，不能证明玩家链路成立。本文件与配套文件是下一轮产品优先级依据，不删除历史事实，不把旧提案逐条重新立项。

### 范围纪律

- 九项全部交付玩家可用机制；专项验证、兼容和记录包含在各项内，**不占一个产品名额**。
- 不新增守卫框架、独立审计平台、发布系统、公开 API 或文档重写工程。必要技术工作必须回答“它解锁了哪条玩家路径”。
- 优先在现有 owner 内扩展，人物/资源/知识/地图继续各自单一真源；不要求十八项对应十八个新文件或十八套 UI。
- 跨题材、按需启用；纯叙事局无需被迫使用数值成长、货币或复杂日程。关闭功能恢复原有行为。
- 完成标准是“入口 → 实际结算 → 可见后果 → 保存/重载”，不是导出数量、测试数量或面板按钮数量。

## OP-1｜场景行动桌：从模块操作转为“我现在能做什么”

**现状与真实需求。** `ui/panel.js` 有 training/gear 的独立操作；在 `act/agency/render/inject/panel` 定向检索未发现 research/family 的对应玩家链。`lingqi.route` 是分诊，不执行动作。玩家不应该先知道引擎名才能安排一次研究或家庭支出。

**增量。** 在现有面板/场景入口提供行动桌：按当前人物、地点、持有物、进行中事项显示“可执行/需准备/不可执行”和具体原因。支持开研究、供料、推进、照护交接、共同支出等；沿现有 act/owner 调用完成动作，结果回到当前场景，不另建万能写状态解释器。明确玩家操作与 NPC 自主提案不同权限。

**数据与接线。** 行动桌只保留选择状态；活动状态仍在各 owner。接通研究/家庭的受众限定叙事块和切聊天读取，不能把所有秘密项目全量注入。统一回执的对象引用与“下一步”展示，复用既有 action/plan，不双记进度。

**玩家验收。** 新局中不写控制台代码即可立项、供料、完成并制造；照护交接后能在同一场景看到负责人改变。缺料时列出所缺资源、库存不变；关闭研究时没有研究操作残影，也不阻断普通配方。

**优先级/成本/依赖。** P0，L；依赖现有 owner。本项不等待全部未来联动，先交付最短可玩路径。

## OP-2｜能力—工具—行动结果联动

**现状与真实需求。** 成长、装备、对抗均已存在，但定向入口检索没有证明普通行动会消费新 training/gear；`gear.use` 目前主要结算使用次数和耐久。只涨数字却不改变选择，成长缺少意义。

**增量。** 让已声明能力决定可用方法，让具体物件的功能/状态影响方法可行性与成本。训练后开放替代解法，而不只是统一加成；有工具但不熟练、熟练但工具损坏应产生不同结果。非数值题材可使用“可做/需协助/暂不可做”的阶段规则。

**数据与接线。** 能力定义继续引用 entities/training，物件引用 gear 的 id。方法需求在题材定义处声明，由 act/contest/production 的实际选择消费；提交后才扣耐久和费用，同一动作不被多个模块重复收费。不要在命中检定、工具和训练三个地方叠加同一效果。

**玩家验收。** 同一维修任务分别用新手+完好工具、熟练者+损坏工具、熟练者+完好工具执行，至少产生两条有依据的不同路径；取消选择不磨损，借出工具后原持有人不能继续用，重载后阶段和物件状态保持。

**优先级/成本/依赖。** P0，XL；入口复用 OP-1，可与其并行开发。

## OP-3｜同一段时间只能花一次：劳动与日程结算

**现状与真实需求。** production 有工期和排班，life 有日程，research 有阶段，survey 有跨日勘察；尚未证实这些占用共同消费同一人物时间。研究每次 advance 也没有真实时间投入。各自合理的进度可以合起来让一个人同时做四件事。

**增量。** 把旅行、研究、生产、休息、照护接到已有故事时钟与日程；按半日/班次等题材粒度处理人物、设备与场地占用。提供暂停、委托、换班、缩减规模，长任务按可用时间推进，玩家能在一天结束时看到取舍。

**数据与接线。** 日程/占用是 life 与现有调度的职责，项目只引用时段及工量，不新建第二时钟。先落“手动推进一日”的确定模式，再接既有离线推进；墙钟/手机后台时间不默认等于剧情时间。工单中途换人、工具损坏、授权变化要有题材明确的暂停/续作规则。

**玩家验收。** 同一个人同一时段不能既出门勘察又在作坊满额生产；交给有资格的另一人后生产可续，代价是另一人的原计划延期。暂停不消耗下一阶段材料，重载不多推进一天，纯叙事模式可关闭细排班。

**优先级/成本/依赖。** P0，XL；与 OP-2 共用资格判断，按现有调度接线，不重写调度内核。

## OP-4｜研究从“确认字符串”走到可验证、可传播的成果

**现状与真实需求。** 当前修复已经保证耗料、失败线索与制造授权，但 evidence 是显式字符串确认；资料/设备/时间没有自动证明，tool/method 成果未形成同等消费路径。传播范围改变使用权，不等于接收者已经学会或知道。

**增量。** 提供类型化前置：引用 intel 资料、gear 设备、training 能力、production 设施与 OP-3 工时；保留题材作者显式确认型作为可选类型。成果分别落到已有配方使用权、工具操作方法、行动方法；公开、转交、演示产生真实认知获得过程，失败线索可减少重复准备，但不自动送进度。

**数据与接线。** 项目存前置引用及验证证据，不复制资料正文和配方定义。canUse 管授权，intel/noesis 管知道，training 管掌握，三者不能互相替代；配方是否受研究限制由题材显式声明，兼容本次“已立项才受限”的旧语义。未完成旧项目需预览 consumed/evidence 迁移，不猜测历史扣料。

**玩家验收。** 没设备时不能靠写“设备已到位”通过设备型前置；失败确实耗料并给出可复用线索；取得资料但未获使用权、获授权但没学会、三者齐备各有不同制造结果。关闭机制后普通配方仍可用。

**优先级/成本/依赖。** P0，XL；依赖 OP-2/3 的资格与时间接口。与 IN-5 的分工：本项完善单项成果闭环，IN-5 增加技术家族和地方分化。

## OP-5｜共同生活经营：预算、分工与责任交接

**现状与真实需求。** family 当前有共同池、照护和均分继承；长期目标、周期支出、自定义分配和责任继承未完成。资产变化不等于一个共同生活单位在运转。

**增量。** 支持成员约定的周期预算、贡献、照护轮值、共同目标、临时困难与协商；租住、合伙、家庭、船员小组等都能使用。退出或显式继任时，资产、支出责任、照护、共同项目分别选择接手，不强制婚姻或血缘结构。

**数据与接线。** 资产继续走 people/org 与 family 共同池，日程用 OP-3，承诺用 life。继承增加具名比例/资源最小单位与事件引用，重复执行同一事件不再付款；不可转移他人的秘密、记忆或能力。未知历史交接不自动猜成完成。

**玩家验收。** 一名成员外出造成收入与照护缺口，玩家可改预算、请人、延期目标，至少两条解法真的改变资金和日程；三人按比例分配微量资产守恒，负责人交接不等于知识共享。退出成员后旧承诺显示明确处置。

**优先级/成本/依赖。** P1，XL；依赖 OP-1/3。IN-8 的长期社会遗产不在本项重复建设。

## OP-6｜世界会留下痕迹：后果真正改变可行动空间

**现状与真实需求。** causal 已结算回声，aftermath 已有地点影响和修复，且部分通道解除已联动；不能说“后果从未生效”。需要补的是各种后果到交通、生产、活动、生活的可见消费覆盖，而非继续加一层后果账。

**增量。** 为已支持地点效果建立明确的业务映射：设施损坏影响工位/工期，封路影响路线/交付，公共场所停用影响活动排期；修复投入材料、时间与合适人员，恢复相应能力。失败不只显示红字，而是创造绕路、改期、协商等行动。

**数据与接线。** 后果状态仍由 aftermath/causal 持有，world/production/activity 读取受影响能力；派生结果通过原 owner 结算，不让一句自由文本随意改所有世界字段。区分“到期”“已处置”“已修复”，不把时间到点当自动修复。

**玩家验收。** 一处桥梁失修使路线和交货时间改变，改走另一条已存在路线能交货；投入维修后通行恢复但历史成本不回滚。重复场景描写不重复损坏，消息尚未传到的人不会先知道。

**优先级/成本/依赖。** P1，XL；依赖 OP-3，复用既有后果及路线机制。

## OP-7｜让角色按自己手里的版本行动

**现状与真实需求。** intel/rumor/noesis 已有真伪、传播跳数、版本和在岗知情边界；relation-graph 已有持久关系。待完善的是“信了什么 → 为什么选这个行动 → 被纠正后怎样变”，不能再只在注入末尾提醒不得全知。

**增量。** 行动前生成角色局部事实视图：本人所见、听闻版本、确信程度、来源与过期信息。life/agency 用这份视图选择调查、询问、等待、合作；新证据改变信念与后续行动，已经造成的损失与关系裂痕不被擦除。

**数据与接线。** 复用 intel/rumor/noesis 的已知判据，不另存完整世界副本。关系变化引用已发生事件与角色评价，防止同一句传言在情绪、关系、舆论里被无意多算；关键不确定事实必须保留来源。

**玩家验收。** 两人掌握同一事件的不同版本时行动不同；公开更正只影响实际收到更正的人，曾因误会取消的约定不会自动恢复。玩家可以用见证、交谈、提供资料促成和解，而不是直接改好感值。

**优先级/成本/依赖。** P1，XL；与 OP-1 联动。IN-3 才增加“我认为你知道什么”的二阶社会认知。

## OP-8｜场景与历史按因果讲清楚，而不是堆模块摘要

**现状与真实需求。** story-loop、story-choice、beat、chronicle-view、sediment 已有场景与历史组织；chronicle-view 的 causal 行读取 title/key/id、summary/note，而 causal 主体多用 action/immediate，存在需要行为验证的可读性缺口。并行场外事件也已存在，不必重建。

**增量。** 当前场景只呈现相关人物、地点、待处理变化和可采取行动；已结束事项给出“做了什么、付了什么、影响谁、留下什么”。历史可从一件物品、一个地点或一次决定追溯已证因果；场外变化经实际感知/传讯进入当前视角。将核心变化转成叙事条件，不要求正文输出仪表盘。

**数据与接线。** 优先补 chronicle-view 字段映射和已结算来源链接，按可见性与当前场景聚合现有 buildBlock；完整状态不重复注入。beat 管节奏，不为制造高潮捏造后果；新场景读取实际状态，不复制上一场快照继续讲。

**玩家验收。** 完成一次研究或维修后，下一场人物可谈到自己知道的结果；历史能追到材料、执行人和实际受益者，而不是一串 id。重返地点看到留下的变化，场外秘密不会泄露给主角。测手机实际首屏和交互响应，不以 headless 通过代替。

**优先级/成本/依赖。** P1，L/XL；主要消费 OP-4/5/6/7 的业务结果，可提前修已确认字段映射。

## OP-9｜可玩的世界蓝图，而不只是人物与地图快照

**现状与真实需求。** `world-blueprint.js` 的 mechOf 白名单仅 economy/weather/worldSeed/worldBlueprint，MECH_KEYS 仅 enabled。现有导入/校验/场景起点是真功能，但不足以复制已配置训练、工坊、研究与共同生活的玩法规则。

**增量。** 蓝图分开保存静态玩法定义、初始条件和可选开场场景：训练阶段/方法、装备槽/功能模板、配方/设施、研究前置、共同生活规则。提供三份可直接开局的跨题材样例：城镇工坊与家庭生活、探索聚落、科幻站点；同一规则可换主题而不是只换名词。

**数据与接线。** 沿用 worldBlueprint 的导出、预览、导入；只补各 owner 的定义适配，不导出进行中项目、私有记忆或已知成果进度。导入明确显示依赖缺失和可选玩法，不自动打开全部引擎。不是角色卡市场、发布平台或公开 API 项目。

**玩家验收。** 导出再开新局后，三种样例的配方、训练与设施确实可用；旧局的研究成果、余额与秘密不随蓝图穿越。禁用一个可选玩法仍可开始基础剧情，玩家不必手填 JSON。

**优先级/成本/依赖。** P1，XL；定义随 OP-2/4/5 与创新线稳定后逐批接入，现有导入协议保留兼容。

## 三个大更新批次与交付方式

下表与创新计划共享同一排期，十八项只计算一次；XL 表示跨多条业务链，不是工时承诺。

| 大更新 | 纳入项目 | 玩家能完整玩到的主题 |
| --- | --- | --- |
| A：人物有取舍，知识能做事 | OP-1/2/3/4 + IN-1/2/5 | 安排一天、选择方法、研究新技术、错失机会后调整生活 |
| B：社会会回应，地方会改变 | OP-5/6/7 + IN-3/4/6 | 共同生活、协商规则、建设/维护设施、处理误解与公共事务 |
| C：世界会积累自己的历史 | OP-8/9 + IN-7/8/9 | 环境反作用、社会遗产、制度与技术改变时代，蓝图重玩 |

批内先接可玩的纵向链，再扩充方法与题材；可以内部多次提交，但不把一个名义大版本拆成九轮“加字段即完成”。每项至少包含主成功路径、一个有意义失败/替代路径、保存后续玩；改 UI 必须安排真实宿主手机视口验收。全量回归只在用户后续明确授权时执行，本计划不自行恢复旧的全量安排。

优先降低重复输入、重复操作和无效注入，让玩家在正常游玩中使用机制。必要专项与说明跟随功能完成，不以新增守卫数量、注释长度、导出数或测试总数评价进展。

设计取舍见 [本轮规划笔记](../.agents/notes/proposed/architecture/2026-10-22-worldaxis-world-first-plans.md)。
