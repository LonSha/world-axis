# WorldAxis V10 Release Readiness Plan

> 状态：提案。基线：`2.295.0` / `2434588` / `origin/master`。本计划不是 V10 新功能双九项；它先把 V9 从“专项已验、全量零失败凭据未取得、真实宿主未验”推进到可发布或可审慎延期的事实状态。

## 一、命题

V9 已交付十八项产品能力，但当前仍有三个发布阻塞事实：

1. 第九趟全量回归按用户指令停止，不能声明 `node tests/run.js` 全量通过。
2. Chromium/CDP 桩宿主专项不能代替真实 SillyTavern 宿主验收。
3. `NEXT_PLAN.md` 和历史计划仍含旧时代入口文字，容易让下一轮把已交付 V9 或历史欠账重新立项。

V10 的第一目标是**建立可复核的发布资格**，不是继续增加功能数量。任何现场验收暴露的稳定产品缺陷，单独记录为 bug-fix 或下一代功能提案，不在本计划中偷塞实现。

## 二、范围与非目标

### 纳入

- V9 全量回归：在源树冻结下重新完成 `tests/run.js`，取得 `result.json` 三要素：`status=passed`、摘要失败为 `0`、`unchanged=true`。
- 真实 SillyTavern 宿主验收：覆盖 V9 关键入口、面板设置、注入正文、托管推进、变化摘要、归档续接，以及至少一组旧局恢复与失败拒收路径。
- 桌面与移动视口证据：记录交互序列、控制台、操作后状态、重载后状态；无真实手机时明确记为阻塞，不用桌面缩放替代。
- 存储与长局压力证据：对 V9 新增存档/续接、事务确认、容量与注入预算进行真实环境基线采集；没有设备就保留待验收。
- 发布事实报告：版本三方、工作树、全量读数、证据索引、错误码、模块/消费者账本、宿主验收矩阵统一生成并审阅。
- 计划与历史入口清理：`NEXT_PLAN.md` 只指向 V10；V9 计划保留历史事实，但修正明显反事实的“未提交/未推送”表述，不改写旧决定。

### 不纳入

- 不因为全量回归缺凭据而改产品行为、降低断言、扩大容差或删除功能。
- 不把 mock、Chromium 桩宿主、桌面模拟触屏或专项锁写成真实宿主/手机通过。
- 不在发布闸门未闭合前追加新的双九项产品线。
- 不建设公共发布平台、联网多人服务、自动升级器或新的独立状态系统。
- 不重写历史计划和历史 Agent Note 以制造整洁的伪当前状态。

## 三、验收分层

每项证据必须标注层级，层级不能互相替代：

| 层级 | 证据 | 可证明内容 | 不能证明 |
|---|---|---|---|
| L0 | 源码/契约/账本门禁 | 结构、登记、边界和静态不变量 | 运行时宿主行为 |
| L1 | Node 专项与全量回归 | 隔离运行时的功能与回归结果 | SillyTavern 生命周期、真实布局和手机压力 |
| L2 | Chromium/CDP 桩宿主 | 浏览器交互、DOM、ARIA、折叠、面板事件 | 真实 SillyTavern 扩展加载、聊天切换和第三方扩展共存 |
| L3 | 真实 SillyTavern 桌面宿主 | 扩展加载、面板入口、聊天/楼层/生成生命周期和状态持久化 | 手机真实压力，除非设备实测 |
| L4 | 真实手机或等价实机 | 触屏、前后台、长局、存储与性能 | 未覆盖的玩家路径 |

发布最低要求：L0、L1、L2 全部有当前提交证据；V9 关键路径至少达到 L3；涉及手机/性能/存储的结论必须有 L4，或明确列为发布阻塞并延期发布。桩宿主通过永远不能单独满足 L3。

## 四、执行批次

### R0：事实基线与环境锁定

- 固定提交 `2434588`，确认工作区干净，生成版本/提交/source digest。
- 运行 `git diff --check`、`tools/evidence-index.js --check`、版本面、拒收面、模块周期、死导出、消费者和文档门禁。
- 建立宿主验收矩阵，逐条列出入口、前置状态、操作、预期状态、重载状态、证据路径和层级。
- 结果只有“可开始”或“环境阻塞”，不把环境阻塞改成产品通过。

### R1：全量回归闭环

- 源树冻结，使用已重算的测试与外壳预算运行 `node --max-old-space-size=4096 tests/run.js`。
- 保存任务目录、完整日志和 `result.json`；只接受三要素同时满足的全量通过。
- 若失败，先按稳定产品回归、测试判据跟位、环境/资源扰动三类分流；每条必须单独复跑并写理由。
- 若环境再次中断，记录准确原因和已完成节数，不把子门禁摘要升级成全量结论。

### R2：真实 SillyTavern 桌面宿主矩阵

优先覆盖一条最小但完整的 V9 玩家路径：

1. 新局导入或建立世界，面板设置可见且可读写。
2. 一次成功推演，确认正文出现暗流推进、owner 内容、拍账、机会/研究/家庭等公开注入。
3. 面板查看注入预算、世界变化摘要和设置检索，确认只读项没有写入副作用。
4. 归档导出、换聊天、续接预览、事务确认，确认轮号归零、托管关闭、原局不变。
5. 触发拒收、关闭模块、重载页面、切换聊天，确认拒收码、状态归属和恢复结果可解释。

每条路径保存交互序列、浏览器控制台、最终状态快照、重载后状态快照；缺任一类证据即为未完成，不用截图单独顶替状态证据。

### R3：移动/存储/长局现场

- 桌面与真实手机分别记录关键路径，不以 CSS 缩放代替手机。
- 采集前后台恢复、聊天切换、连续推进、存档/续接、容量上限和失败恢复的 p50/p95 或明确样本数。
- 对 V9 新增持久记录执行“写入、重载、读取、拒收、版本不匹配”路径。
- 现场不可用时提交环境阻塞记录，保持发布状态为 blocked，不修改阈值。

### R4：发布事实报告与裁决

- 运行已有 `tools/fact-report.js`、证据索引、版本/文档/工作树检查，并新增或补齐宿主矩阵汇总。
- 报告按“通过 / 阻塞 / 未覆盖”分列，禁止把未覆盖并入通过。
- 只有 R1 全量通过、V9 关键 L3 宿主路径通过、发布报告一致且工作树干净，才具备桌面发布候选资格。
- 任一关键路径失败或 R3 未取得所需实机证据，状态为 `blocked`，提出下一条最小修复或现场计划，不开新功能线。

## 五、关键路径矩阵

| 路径 | 最低层级 | 必须证明 | 失败处理 |
|---|---:|---|---|
| 面板加载与设置写回 | L3 | 面板分区、控件、设置持久化、重载后状态 | 宿主 bug-fix；未加载则阻塞发布 |
| 成功推演正文注入 | L3 | V9 owner/暗流/拍账/机会等公开内容按边界出现 | 逐源归因；不靠扩大正文快照容差 |
| 预算看板与设置检索 | L3 | 逐源读数和当前页过滤准确，检索不改值 | UI 或数据契约 bug-fix |
| 变化摘要 | L3 | 仅成功推演区间的公开投影，隐藏/私密不泄漏 | 隐私/范围问题为发布阻塞 |
| 归档续接 | L3 | 白名单末态、预览确认、轮号归零、原局不变、丢尾拒收 | 续接状态或存储问题为发布阻塞 |
| 拒收与重载恢复 | L3 | 拒收码、事务回滚、聊天切换和重载后状态一致 | 不允许静默降级 |
| 手机/长局/存储压力 | L4 | 真实设备数据与冻结预算 | 无设备则明确延期，不报通过 |

## 六、状态规则

- `candidate`：R0、R1、R2 通过；R3 相关项目有真实数据或明确不属于本次发布范围。
- `blocked`：全量失败、关键 L3 路径失败、证据不完整、工作树不干净或版本报告不一致。
- `deferred`：产品可发布但手机/长局等非本次目标现场数据未取得；必须在发布说明中明确限制，不得写成全部验收通过。
- `released`：仅在用户明确授权发布并且 `candidate` 复核后产生；本计划本身不自动发布。

## 七、计划完成条件

1. `result.json` 明确为全量 `passed`、失败 `0`、`unchanged:true`。
2. V9 关键路径在真实 SillyTavern 桌面宿主达到 L3，矩阵证据完整。
3. 证据索引无 stale；版本、错误码、模块、消费者、文档和工作树报告一致。
4. 所有未覆盖项单独列出，不被“专项通过”或“浏览器通过”掩盖。
5. 若有现场缺陷，完成最小修复后重新过受影响专项、R1 和对应宿主路径；若是环境阻塞，保留 blocked 记录。
6. 完成后再由用户决定是否发布或立项真正的 V10 产品功能。
