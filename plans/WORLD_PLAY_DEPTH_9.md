## 这次优化什么，不优化什么

主题是“让镜头之外的世界自行运转并推动剧情”。当前不是缺少模块名，而是玩家在正常入口安排的事情，尚不能稳定贯穿人物、时间、物件、地点、认知和后续场景。旧 OP/IN 十八项已有代码，不再按“全部未开始”重做，也不按接口存在判定完成。

本线只计算 **WP-1～WP-9 九个产品项目**。每项内部包括业务逻辑、正常界面、续玩和所需验证；测试、兼容、性能和记录不另占名额。各项工作量是基于当前跨文件缺口的**初始工程估算**，不是对 AI 墙钟速度的保证。共享功能只计算一次，详见排程。

- 继续复用 `store/commit/exec/playtime` 和已有业务 owner，不新增万能执行器、第二套库存、第二个时钟或“世界总管”。
- 玩家行为必须走正常 UI 或既有剧情行动入口；模型只提议和表达，不凭一句“成功了”代扣材料、改身份或完成任务。
- 保留纯叙事、精细模拟的可选性。玩法关闭时不偷跑，也不为了依赖方便自动开启所有模块。
- 本轮不做守卫平台、公开 API、发布链、自动计划生成器、全库重构或文档重写。已有正确性要求继续履行，但不再以守卫数衡量进展。
- 下列验收均指**未来实施的完成条件**；本轮没有真实 SillyTavern/手机验收。无头专项与补充探针的边界见证据文档。

## WP-1｜真正能办事的场景行动桌

**需求与现状依据。** 行动桌已有路由、分组和按钮，不是空白。`action-desk.board/fromProduction/plan` 与 `ui/panel.js` 的 `showDesk` 表明：列表仅聚合五类来源，地点没有完整参与筛选；按钮仅传 `{who}`；暂停工单展示“可续作”，实际 `production.advance` 要求先复工。缺的是“办完事情”，不是再加一排按钮。[证据 E01](WORLD_PLAY_BASELINE_2026-10-24.md#e01)

**必须交付的工作包。**
1. 人物、地点、当前事项作为同一操作上下文；只展示可知且相关的对象，不把全局工单和所有方法都列为当前行动。
2. 为本轮支持的动作补齐对象、数量、材料、接收人、时段、方法等具名表单；只对已有业务类型声明输入，不做任意 JSON 编辑器。
3. 提供准备、确认、执行、进行中、结果与下一步交互；开单、供料、停工补料、复工、交货、换班、转交物件均能从结果继续走，不再把 owner 拒收显示成成功。
4. 贯穿 PC/手机的最短操作路径，保留当前人物和待办上下文；关闭模块移除对应动作，切聊天清除旧选择。新增 WX 玩法复用这一入口，不另开九套管理面板。

**玩家完整路径。** 看见缺料工单 → 选择供料人和数量 → 补料 → 复工 → 安排可用班次 → 交付 → 在同一结果卡进入运输或委托。

**结项下限。** 至少覆盖生产、物件、排班、共同生活、出行五类十种有完整入参的动作；每类走一次主路径和准备不足分支。暂停按钮必须实际恢复工单；失败不清掉未完成选择；重载后从业务状态重建，不依赖上一屏缓存。不得用控制台补参完成演示。

**依赖/边界/估算。** P0；A 包；**8–12 小时**。先交付既有能力的入口，后续按原契约扩表单；不重复 WP-2～7 的业务结算预算。

## WP-2｜行动方法真正改变目标，而不只消耗工具

**需求与现状依据。** `action-methods.evaluate/execute` 已有技能和工具路径。补测发现：不存在的维修目标也能返回成功，同样参数再次执行又扣耐久；当前函数返回路径描述但不提交维修目标状态。`gear.repair` 已有真实材料与耐久结算，应复用。[证据 E02](WORLD_PLAY_BASELINE_2026-10-24.md#e02)

**必须交付的工作包。**
1. 给具名方法绑定目标类型与实际业务执行：首批为物件维修、设施抢修、工单加工三族；每族至少两种有不同资格/时间/材料取舍的方法。
2. 方法预览同时给目标可变部分、费用与所需时段；执行时把方法选择落实为真实目标变化，而不是仅返回 `path`。
3. 原 owner 持有资源和目标状态。方法层只编排一次投入与结果；中途失败保留已经合法付出的代价，取消准备不扣费，不把部分完成伪称整项完成。
4. 玩家重复确认绑定同一行动身份；新开一次工作是新行动。借出的工具、损坏工具、换人续作、目标已完成分别有明确行为；自定义方法随本局定义保存和恢复。

**玩家完整路径。** 新手借到工具选择慢修 → 工具磨损迫使停工 → 请熟练者续作 → 目标恢复功能 → 归还的仍是同一件物品，实际耗时和成本留存。

**结项下限。** 三族目标、每族两种方法；相同任务在技能/工具条件变化后至少产生两种实际结算结果。验收读目标、库存、工具和日程，不只读返回值。目标不存在不扣费；同一确认只结一次；取消和重载后可续作；不用任意脚本作为方法定义。

**依赖/边界/估算。** P0；A 包；**10–14 小时**。依赖 WP-1 输入与 WP-3 时段契约；WP-7 负责地理影响和服务恢复，不能两边重复修同一设施。

## WP-3｜一天只有一天：跨业务劳动与世界日结

**需求与现状依据。** `labor-schedule` 的预约互斥是实际功能，但独立 `currentDay` 与 `playtime.story()` 未统一。补测剧情第七日时推进预约日，预约变第二日、剧情仍第七日；生产、旅行等本次定向检索未见消费该预约。不能把预约表内互斥当成现实业务已互斥。[证据 E03](WORLD_PLAY_BASELINE_2026-10-24.md#e03)

**必须交付的工作包。**
1. 选定已有剧情钟为日历依据，预约只引用日期/时段，不再自行维护第二条推进线。旧预约先给出可解释映射，日期不明不猜已完成天数。
2. 生产、旅行、训练、共同生活值班和维修五类业务消费同一人物可用时段；地点与途中状态参与判断，设备/工位占用仍由各 owner 负责。
3. 正常“结束时段/推进一天”完成到场、劳动、产出、关系/承诺反馈；手动与既有自动生命周期复用同一结算逻辑，不因连续点五次就制造五天工量。
4. 换班、拆分工量、延期、取消、跨日长任务提供实际替代方案；离线恢复仅在已有授权模式下消费明确剧情区间，不把手机离开时长默认兑换成工时。

**玩家完整路径。** 上午要赶路又要加工 → 选择委托同伴 → 同伴原计划顺延 → 当天只完成可用工量 → 次日续作，得到与安排一致的成果。

**结项下限。** 五类业务混排，至少三人、三地、连续七个剧情日；旅行中的人不能同时到场劳动。同一时段重复推进不增加产出；暂停不扣下一时段材料；换班真实改变两人的可行行动；剧情跳日与重载均能延续。无细排班模式保留粗粒度原玩法。

**依赖/边界/估算。** P0；A 包；**12–18 小时**。是多条玩法的共同前置，但实现归本项，不另立“调度治理”项目。沿 `life/agency/world/production/playtime` 接线，不重写它们全部内核。

## WP-4｜技艺、制造与交付成为一条经营链

**需求与现状依据。** 生产已有预留、耗料、停工、交货和货运。技艺前置层 `research-closure` 已有设备/技能/预约查询，但 `intel` 类型未见独立分支，预约只验证时段存在，且未等于完成工作；`tech-lineage.canProduce` 仍主要是独立查询。这里的知识与试制均指**虚构工艺、机械与游戏规则**，不是现实生命科学研究。[证据 E04](WORLD_PLAY_BASELINE_2026-10-24.md#e04)

**必须交付的工作包。**
1. 将“有图纸/有使用许可/会操作”分别接到真实来源；方法和配方依赖按题材显式声明，不把所有普通制造强制改为先解锁。
2. 工单消费方法、师承资格、已完成工时和设施能力；设备不足可租用，技能不足可雇工，图纸缺失可通过游戏内交谈或采购获得，不只有一个禁止按钮。
3. 订单从接单到备料、生产、入库、运输、签收、报酬完整贯通；暂停、延期、部分交付和取消分别处置，已消耗的材料不随取消凭空退回。
4. 操作期间学到的方法与已验证的产品质量反馈后续选择；固定采用题材声明的离散规则，不用文本判断自动创造新配方或真实技术参数。

**玩家完整路径。** 接到机械配件订单 → 有图纸但不会做 → 请师傅协作并占班 → 缺料停工 → 改买材料或缩量 → 完工、运输、签收 → 报酬和经验产生不同后果。

**结项下限。** 两类非生物工艺、至少一条多步制造链、两条供料/技能补足路线；实际检查库存、入库一次性、在途货物、签收与支付。文件或许可获得不能直接变成技能；已预留材料不可被另单再用；中途换人和跨日重载可续作。

**依赖/边界/估算。** P0；A 包；**10–16 小时**。依赖 WP-2/3，复用 `production/economy/freight/commission/training/tech-lineage`。只改善单单经营与资格消费；地区标准兼容、扩散和改装投资归 WX-5。

## WP-5｜NPC 的动机、所知与经验进入真实决策

**需求与现状依据。** `motive-arbitration` 有候选评分，`path-echo` 有预期和学习，`epistemic-view` 有信念视图；但 `life.decide` 仍按固定条件返回，未见其在正常决策中调用新比较器。预期回声直接修改取出的 person，持久化与未来消费尚待专项复现。认知不能另起一套事实真源。[证据 E05](WORLD_PLAY_BASELINE_2026-10-24.md#e05)

**必须交付的工作包。**
1. 将真实目标、承诺、资源、恢复需要和可用时间组装为少量候选，接入 `life→agency→plan→act` 正常链；危急硬约束保留，普通选择再比较动机。
2. 候选只能读角色经 `intel/rumor/noesis` 得到的局部信息。已知、相信、传闻版本、对他人的推测各有来源；更正消息抵达后才生效。
3. 关键选择保存当时的预期；已知执行回执修正具体情境偏好，并实际影响下次决策。复用现有 `path-echo`，不复制全世界反事实副本到每个 NPC。
4. 角色能拒绝、提出条件、延期、补救；理由只解释实际使用的输入。玩家看到“如何改变条件才能合作”，而不是五个隐藏分数或全知内心独白。

**玩家完整路径。** NPC 为挣钱错过约定 → 获知实际损失 → 提出补约 → 下一次相似机会更重视承诺；未收到消息的另一人不获得同样经验。

**结项下限。** 三种人物偏好、至少三类冲突候选、连续五次关键选择；更改真实动机/时间/所知之一会改变相应选择。经验必须在重载后影响下一次真实行动；不知情者不学会全知教训；角色不会每轮无理由反复改主意，也不替玩家自动决定。

**依赖/边界/估算。** P0；A 包；**12–18 小时**。依赖 WP-3；局部信息契约供 WP-8 与 WX-2/7 消费。WX-1 才增加多个 NPC 竞争同一机会的世界结果，本项不重复做竞争结算。

## WP-6｜共同生活按周期履约，而不只是存预算

**需求与现状依据。** `family/family-ops` 已有共同池、预算、缺口方案和比例分配。源码显示雇工主要扣款并记历史，代班未核验 transfer 返回，也未占实际时段；比例分配先清空来源再跳过不存在受益人。该分配风险为静态发现，未宣称已复现或修复。[证据 E06](WORLD_PLAY_BASELINE_2026-10-24.md#e06)

**必须交付的工作包。**
1. 周期预算落实为到期收入/支出与真实履行；共同目标按资金和劳动进展，不按改一个状态就完成。适用于合租、船员、合作工坊、家庭，不强制亲属结构。
2. 值班、家务和共同设施维护连接 WP-3；请人要有可用人物、时间、报酬和履行结果，支付预约不等于工作已经完成。
3. 缺口提供减支、补贴、请人、代班、延期目标等选择；成员同意范围和个人承诺影响可行方案，延期会产生后续问题但不自动制造悲剧。
4. 成员退出或明确交接时，资产、未付义务、岗位和共同目标分别处理；份额精度按资源定义，所有受益人与余量在动钱前确定，不把无效受益人那份吞掉。

**玩家完整路径。** 一人外出使收入和轮值中断 → 协商减少目标支出并请人替班 → 替班者因另一承诺迟到 → 改班补上 → 下周期预算反映真实结果。

**结项下限。** 一个四人共同体跨三周期，至少三种缺口解决方案；雇工/代班真实占时且能失败；退出后每项义务有承担者或明确未解决状态。无效受益人、微量资源、重复交接不丢钱、不重复付款。重载继续原周期，不重新收取整期费用。

**依赖/边界/估算。** P1；B 包；**10–14 小时**。依赖 WP-1/3/5；只负责共同生活内部履约，跨组织互惠与多方承继归 WX-3/8。

## WP-7｜设施、道路与服务真正改变可行动范围

**需求与现状依据。** `aftermath/world` 已有道路和修复。补测 `commissionRepair` 在 owner 返回 `not-found` 时仍报 repaired；`findDetour` 默认捏出绕路节点。`service-network` 的容量/负载是实际记录，但启用主要改状态，queued 未见可续办队列，degraded 未直接降低有效容量，地点读取与 world 真源还需统一。[证据 E07](WORLD_PLAY_BASELINE_2026-10-24.md#e07)

**必须交付的工作包。**
1. 设施施工、启用、使用、维护、损坏、修复由实际工单与回执驱动；完成维修才恢复相应能力，不让外层固定返回成功。
2. 地点、道路和服务覆盖取既有地图；两类首发服务为加工工位和驿站/中转。没有道路就没有可走的“默认绕路”。
3. 容量影响可预约、等待、改约与替代服务；排队条目可续办/取消，服务降级真实减少吞吐，供应中断影响依赖者，不能只画网络图。
4. 给出就地等待、异地租用、抢修、改线的实际成本和时程；恢复功能不抹掉延误、费用、失约或已发生的物件磨损。

**玩家完整路径。** 公共工位停用 → 原订单排队 → 租另一处需绕行且费用增加 → 部分成员留下抢修 → 恢复后原队列续办，受损历史仍可追溯。

**结项下限。** 两类服务、三个地点、至少一条替代路线；集中与分散布局在一次普通故障后有不同业务结果。不存在目标不扣费也不报修好；无路不编节点；排队、维修、运输跨日和重载后可续。按功能影响显式映射，不靠中文关键词判断道路是否损坏。

**依赖/边界/估算。** P1；B 包；**12–18 小时**。依赖 WP-2/3/4；复用 `operations/production/world/freight/aftermath/service-network`，不建立通用网络仿真平台。

## WP-8｜只讲当前人物能够经历的场景与因果

**需求与现状依据。** `scene-narrative.currentScene` 直接取人物表前六项，`perceivedHorizon` 取公开 horizon 条目，未核对该人实际收到；补测可把远方人物列为在场、把无获知记录的公开远方消息列入视图。`traceFrom` 的字符串命中也不等于因果链接。这里的需求是准确且有戏可接，不是新日志中心。[证据 E08](WORLD_PLAY_BASELINE_2026-10-24.md#e08)

**必须交付的工作包。**
1. 场景人物以 `world.where`、已到场活动与实际位置为依据；途中、不明位置、远方各自表达，不能把人物名册当在场名单。
2. 当前场景接收已发生、已可知、与人物/地点有关的变化；行动、代价、受影响者、下一步各有业务来源，未知部分保持未知。
3. 从物件、地点、任务打开相关历史，按明确引用追因果；场外消息经原传播链到达后才进入该观察者视图，作者全知模式与角色模式分开。
4. 接入原叙事注入与 `beat/story-loop`：一轮重点少而明确，结果不连续重复，失败生成不吞掉待讲变化。为 WX 长期剧情保留对象链接，不全量灌入十八个模块摘要。

**玩家完整路径。** 玩家在别处错过工坊事故 → 途中暂不知情 → 消息抵达后可询问 → 返回看到真实停工与维修 → 点物件查到实际受损和修复过程。

**结项下限。** 两个视角、三地、消息延迟、改地点与返回；未知消息不进角色 prompt/可见界面，远方人物不冒充到场。同一结果下一轮可接戏但不重复当新事件；历史以真实来源连接，不能仅按标题含词匹配。手机首屏与操作另走真实宿主，不用无头读数替代。

**依赖/边界/估算。** P1；B 包起交付，C 包扩展；**8–12 小时**。WP-5 持有知情与决策规则，本项只消费；不建立第二套人物认知或历史事实库。

## WP-9｜蓝图能安装玩法，并从第一天持续玩下去

**需求与现状依据。** `worldBlueprint` 已有结构导入；`playable-blueprint` 现有三套定义摘要和对象存在性检查。补测 training 关闭时仍 `canStart:true`；该文件没有安装器。不能将“三条样例名字”当作三种能玩的开局。[证据 E09](WORLD_PLAY_BASELINE_2026-10-24.md#e09)

**必须交付的工作包。**
1. 复用原预览/确认/导入，把训练、方法、物件、配方、设施、时段、共同体规则写入各自 owner 的定义面；初始条件和运行进度分开。
2. 空局向导显示安装内容、需要启用的玩法、可选降级和实际缺口；不要求手填 JSON。导入既有局必须明确冲突，不能默默覆盖玩家资产与人物。
3. 交付城镇工坊、商路驿站、科幻维修站三种玩法包；分别突出共同经营、移动与履约、设备与服务依赖，不能只换地点名字。
4. 每包含首日任务、继续七日的动机/资源/关系来源及至少两个选择分支；本线与 WX 的静态规则随能力逐批进入蓝图，运行中的秘密、学会进度和未结算义务不进入新局模板。

**玩家完整路径。** 新聊天选择维修站 → 预览与确认 → 首日领取真实工具、排班、接单 → 缺资源选择外送或协作 → 七日后保存 → 导出规则另开一局，保留玩法而不复制旧局历史。

**结项下限。** 三包各完成至少七个剧情日，至少一包联合 WX 跑三十轮；普通用户只用界面可开局。保存重载、关闭一个可选模块、旧格式导入、非空目标均有清楚结果。导出后新局规则可用，旧局余额/秘密/技能成果不穿越；“可开始”依据实际可玩的能力，而非模块对象存在。

**依赖/边界/估算。** P1；A 包先落安装骨架，C 包全部交付；**12–18 小时**。依赖 WP-1～8 的稳定业务契约；每个 WX 自付其规则适配，本项只计算通用安装、三包初值和整局体验。不做模板市场、云同步或外发平台。

## 总量、完成标准与收口

本线估算 **94–140 小时**。三大更新与创新线合并执行，不是九轮微更新；依赖、逐日顺序与总工作量在[共享排程](WORLD_PLAY_BASELINE_2026-10-24.md#schedule)只维护一份。

每项结项必须同时满足：正常入口可操作 → 原 owner 实际变化 → 当事人可知的反馈 → 至少一条失败/替代路径 → 跨时段与保存重载可续。源码、无头行为、真实宿主分别记录；某一层未验就明写未验。小范围修好一个返回值、跑绿旧专项或补几个字段，都只算该项内部进度。
