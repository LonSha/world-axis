## 产品范围

用户指定的前五个方向是：真实势力外交、人物行动闭环、区域供需、可游玩分支、完整世界蓝图。后四项沿这些能力形成委托履约、情报调查、地点后果和组织运营。每项都以玩家操作、世界结果、可知反馈和重载持续性作为交付单位。

继续采用零依赖、IIFE 与 window.WorldAxis，不建设公开 API、多人服务、对外发布链或另一套独立状态系统。外交关系、库存、人物身份、真相和组织权限各自保留一个真源；新模块优先作为已有引擎的协调消费者。

## 九项拓展

### TX1 可谈判、可履约的势力外交

- **优先级**：P1；第一核心玩法。依赖 TP1/TP2/TP4、TX5 的稳定身份与引用合同。
- **已有基础与真实差距**：faction-graph 能从双方各自的对外态度档位推导关系图，边恒为 derived:true，并带 basis；这不是成对外交事实。evolution、inst、org 已提供势力、权限与资源基础。
- **新增范围**：为势力对建立稳定 pairId、双向态度、关系状态、有效条约及变化来源。玩家可提出条件、收到接受/拒绝/还价、确认签约，随后按已声明条件执行通商、互助、停战、禁运等有限条款；违约依据实际回执结算。条约与态度可以相互影响，但不混为一个数值。
- **玩家路径**：选择两个势力和提案 → 权限及资源预检 → 预览条件 → 对方作出有据答复 → 确认 → 条款进入有效期 → 查看商路/资源/关系后果。
- **边界**：未知双方关系保持 unknown；旧推导边保留标签，不自动迁成联盟或战争。未登记的偏好和外交事实不能由公式猜出；纯规则只能执行明确数据，AI 文本提案须经结构预检。签约不自动泄露给未获消息的人物。
- **验收**：A–B 签约不改写 A–C；非对称态度保留；双方权限不足、资源短缺、重复确认、失约、条款到期、切聊天、重载均有状态证据。禁运真实影响适用商路，解禁恢复规则可见；未签约提案不产生正式世界效果。

### TX2 人物动机、计划、行动与反馈闭环

- **优先级**：P1；与外交并行的核心玩法。依赖 TP4/TP5 与 TX5 身份合同。
- **已有基础与真实差距**：life 已有目标、承诺、日程和决策；plan 有步骤、推进与结算；act 有移动、交付、会面和回执；opportunity.take 已经能建行动，liaison 已有约定终态。增量在整条生命周期与反馈，不重做这些接口。
- **新增范围**：以 goalId/planId/stepId/actId/receiptId 关联动机与世界结果；有界调度把可执行决策映射到计划和行动，行动回执驱动步骤结算，结果更新目标进度、相关承诺、关系和人物记忆。失败保留阻塞理由，并在条件改变后重排或由玩家决定放弃。
- **玩家路径**：看到 NPC 当前目标和已知阻碍 → 支持、阻挠或委托 → NPC 安排行动 → 到点获得实际结果 → 计划与关系发生对应变化 → 下轮对话回应结果。
- **边界**：只自动执行可由既有规则判定的动作；tell/work 等需要业务侧确认的结果保持待确认，不能“过了时间就成功”。人物自主性有预算、权限和冲突规则，不能无限新建目标；未获知后果的人物不提前改记忆。
- **验收**：同一目标只建一条当前计划；移动→会面→交付确实改变位置与资源，失败不能推进成 done。承诺和计划消费同一回执，不重复奖惩；日程冲突、资源被他人占用、参与者离开、关闭自动调度、重载与切聊天都有正反场景。

### TX3 区域供需、在途运输与商路选择

- **优先级**：P1；第三核心玩法。依赖 TP4/TP7、TX5 地理/资源身份，可与 TX1 的条约效果联动。
- **已有基础与真实差距**：economy 已有库存、价格、购买、生产、商路和阻断，region 已有远方地点与传播。economy.ship 当前即时增加目的地库存，没有源扣减和运输在途；不能把它当作守恒运输系统。
- **新增范围**：登记各地真实给定的生产/消费规则、需求窗口和价格响应；新运输操作包含源库存或人物货仓、预约/扣货、出发、在途、路线变化、到货与退款/损失回执。世界库存、人物持有和在途货物分别定义归属，库存真源向 org/economy 既有面映射，避免双记余额。
- **玩家路径**：查看自己已知的缺货与报价 → 采购/生产 → 选择路线、费用与预计时间 → 发运 → 遭遇封路或外交限制 → 等待、改道或取消 → 到货后供应与价格真实变化。
- **边界**：未知基础价与生产率不凭空创建；距离、运输时长取明确地图数据，缺少路线就拒算。旧 ship 保留原语义并标注即时补货，或经显式迁移退出；不悄悄把旧存档操作改成新运输。未到货库存不可买，消息传播与实物运输不能共用一个“已抵达”标记。
- **验收**：对每笔货检查源+在途+目的地+已消费/已声明损失的守恒；重复 tick 和重载不重复到货；封路保留货物，改道重新预估，取消按已执行阶段结算。跨区域日窗、条约生效、队列满、资源不足、关闭功能与存储失败不制造货物或负余额。

### TX4 可选择、可兑现后果的故事分支

- **优先级**：P1；第四核心玩法。依赖 TP1/TP4/TP8，复用 rehearsal、exec 和 branch-tree。
- **已有基础与真实差距**：branch-tree 已有 fork/choose/tree/compare/replay；compare 只看 keys/chars/digest 指纹，缺失为 unknown；replay 要求旧预演仍匹配。现有 JSON 记账与预演不是可直接操作的完整分支玩法。
- **新增范围**：轻量面板显示分支节点、可选动作、玩家已知代价和结果预览；每个选项绑定可执行、白名单化的规则操作及预演依赖。确认后通过 TP4 的候选提交协议应用世界结果，树节点记录实际回执；对比提供有来源的关系、资源、地理与关键事件差异。
- **玩家路径**：遇到明确选择点 → 查看已知条件和可选代价 → 预演或直接选择 → 再次复核条件 → 确认 → 世界和后续注入回应该选择 → 回看实际选择与当时预演。
- **边界**：choose 记账与世界应用必须分别可观测，不能因树上有 choice 就说后果已发生；不能把 rehearsal 的任意 diff 直接写进 live store。状态变了就重新预演；过期、未知、不可比较分别显示。反事实回放留在隔离环境，不回溯覆盖当前存档；时光倒流不属于本项。
- **验收**：两个互斥选项产生不同且可解释的实际结果；双击只提交一次，旧预演不能强行确认；切聊天不消费其他聊天的选项。对比只读，unknown 不冒充相同或不同，回放不修改当前世界。桌面键盘和手机触屏均能完成选择并重载延续。

### TX5 版本化完整世界蓝图与可验证新局

- **优先级**：P1；作为共同结构基础在首批之后先行实施，再推进 TX1–TX4。这里的完整指受支持的世界结构，不等于完整聊天存档。
- **已有基础与真实差距**：world-seed 已支持提取、转移、预览、确认与空局检查；旧格式保存显示名、关系档位、地点名、道路数量和时代，不含道路端点、同名身份或事件进度。preset-world / recipe 已有静态配置和题材起点，不能重新包装成新增模板库。
- **新增范围**：新蓝图格式带 schemaVersion、世界观标识、稳定人物/势力/地点/资源 ID、别名映射、关系方向、道路端点/通行条件/时长、时代与日历起点、受支持的静态人设和机制配置。后续外交条款、供需规则、组织结构按版本登记。事件起点是可选的场景模板，显式启用，默认清零历史进度。
- **玩家路径**：导出世界结构 → 选择保留层级和场景起点 → 导入空新局 → 检查身份映射、地图连通与外部依赖 → 查看拟写入结构 → 确认一次安装 → 重载后人物、道路和机制可继续使用。
- **边界**：旧格式依然明确是有损种子，不伪造道路或同名 ID；新格式遇到未知字段/版本/悬空引用明确拒收或列出声明的降级。人物私密记忆、聊天文本、已完成事件、外部凭据和可执行脚本不随蓝图导出。卡/世界书/媒体资产不能嵌入时列为依赖，预览如实提示。稳定 ID 迁移须映射已有读写者，不能只在蓝图里生成一套无人使用的 ID。
- **验收**：含两个同名人物、三势力、带端点道路和日历的蓝图往返，结构/方向/引用一致；新局活动进度为零，启用的场景模板与默认清零可区分。未知版本、重复 ID、断边、权限/容量错误、取消、目标非空、预览后切聊天与并发写入均无半写。老种子仍可用且预览显示真实损失，源聊天逐字不变。

### TX6 多阶段委托、交付核验与资源履约

- **优先级**：P2；依赖 TX2/TX3、TP4/TP7。
- **已有基础与真实差距**：opportunity 已形成窗口、接受/拒绝/延后并能建 act；liaison 已有约定、到期结算、证据及关系影响；org 已有项目、债务和支付。新项只补多阶段合同与可核验资源交付，不重做“接任务”和普通约定。
- **新增范围**：委托具名阶段、期限、交付对象、验收条件、报酬、可选预付/托管与违约裁决；阶段引用 act/运输/项目回执，核验满足后才进入下一阶段或支付。改约、取消和部分履约有明确余额与责任归属，超期不默认认定恶意。
- **玩家路径**：查看已知机会 → 谈定交付和报酬 → 接受 → 执行与交付 → 委托方按条件核验 → 获得报酬和关系反馈 → 后续机会回应信誉。
- **边界**：不根据正文一句“完成了”自动付钱；没有预算的委托不能承诺可领取的奖励。关系反馈复用 liaison 的真源，同一完成证据不由两个引擎重复奖励；托管资源有明确所有者和退回规则。
- **验收**：两阶段委托部分完成不发全额，伪造/不匹配回执不能核验；同一证据不能重复领报酬。超期、改约、委托人离开、资金不足、取消和重载按协议结算，来源机会、行动、约定与库存都能追溯到同一合同。

### TX7 线索调查、证据核验与秘密揭示

- **优先级**：P2；依赖 TX2、TP4/TP8，复用 intel、enigma、noesis、rumor 与 causal。
- **已有基础与真实差距**：intel 已有来源、传播、相信、核验与纠错，enigma 已有秘密知情名单。新项把取证成本、调查选择与揭示权限串成玩法，不再增加一个“真相仪表盘”。
- **新增范围**：登记可发现线索、地点/证人条件、时间或资源成本、相关命题与证据来源；玩家选择询问、查证或勘察，行动产生证据回执，由既有核验规则区分未证实、相互矛盾、已核实与无法判断。证据达成明确条件后才扩展知情范围，后续外交、委托或人物决定消费获知结果。
- **玩家路径**：听到传闻 → 挑选调查方向 → 付出时间/成本 → 获取自己可接触的线索 → 对照来源 → 选择继续核验、纠错或公开 → 看到知情人与世界后果。
- **边界**：传闻不是事实，多人重复转述不能制造多个独立证据；不存在的真实结论保持 unknown。证据采集不自动赋予全知权限；面板预览不露出未发现秘密。调查动作若无法规则确认，就保持待业务确认而不是补造证据。
- **验收**：不同人物对同一线索有不同可见结果；封路/不可接触证人/证据不足阻止核验；伪证能被既有来源约束检出。纠错更新相关认知而不删除历史来源，公开行为只影响实际收到信息的人；切聊天与重载不丢案件引用，不泄密到玩家 prompt。

### TX8 地点历史的实际后果、修复与复访

- **优先级**：P2；依赖 TX3、TP4/TP7，复用 sediment、world、region、calendar/weather 与 economy。
- **已有基础与真实差距**：sediment 已保存地点痕迹、衰减并可注入感知；远方脉搏可显式沉积。新项让有据的历史影响地点条件，并可由玩家改变，不重建沉积存储。
- **新增范围**：以真实事件/回执 ID 登记有时限的地点效果，如道路受损、交易暂停、设施修复中；效果消费于路线、供需和可用行动。玩家能清理、维修、重建或选择绕行，资源与工期规则明确，完成回执更新效果而保留历史痕迹。
- **玩家路径**：进入地点看到自己已知的历史和现实影响 → 选择绕行或投入修复 → 完成材料/工期条件 → 可用道路或设施恢复 → 后续复访看到持续结果和历史来源。
- **边界**：一段痕迹文字不能自动解释成资源惩罚；衰减也不自动证明设施已经修好。效果必须有登记规则，气候影响只取已有明确条件；不重复推进近场/远场，不为未知地点制造物理状态。
- **验收**：同一事件效果只生效一次；道路损坏确实阻止适用运输，修复恢复通行并只扣一次材料；效果到期、工期中断、取消、并发修复与重载结果一致。沉积仍可只读，老地点没有效果规则时不被强行改动。

### TX9 权限批准、组织项目与运营结算

- **优先级**：P2；依赖 TX1/TX2/TX3/TX6、TP4/TP7，复用 inst 与 org。
- **已有基础与真实差距**：inst 已有章程、职位、任免、交接、提案批准、违约核验；org 已有资源、薪酬、项目和债务。inst 明确不动资源，批准后的执行由调用方负责；增量是批准到真实项目和资源执行的消费链。
- **新增范围**：具名政策提案绑定权限、预算、项目执行者、里程碑与结果回执；批准后受控创建/推进 org 项目，资源拨付、采购、薪酬和履约消费同一批准。组织运营按明确剧情周期有界结算，人员交接移交具体项目/义务引用，而非只记录数量。
- **玩家路径**：以当前职位提出方案 → 按权限批准 → 分配资源和人员 → 观察项目进度 → 处理欠薪、供应中断或交接 → 查看实际收益、成本及声誉变化。
- **边界**：保留 inst 的批准真源与 org 的资源真源；只有批准通过不等于项目完成。不能把私人人际关系当批准权；违约罚则仍显式、有据，调职/离任不静默清空旧债。新周期结算不重复 org 已有薪酬或项目支付。
- **验收**：无权提案不能拨款，合法批准只建一个项目；资源不足保留明确阻塞，审批与执行失败不半写。换负责人后具体未完成工作仍有所有者；同周期重复执行、失约、关闭自动运营、切聊天和重载不重复发薪或免债。结果能继续影响适用外交、合同和人物目标。

## 跨项依赖与合版安排

1. 先落 TP1/TP2/TP4 的归属与提交约束，再实施 TX5 的基础格式和运行时身份映射。
2. TX1 与 TX2 合成外交和人物行动的一次完整更新；TX3 与 TX6 合成供需、运输和履约更新。
3. TX4 与 TX7 合成选择、调查和可知后果更新；TX8 与 TX9 合成地点、组织和长局运营更新。
4. TP5、TP7、TP8、TP9 贯穿；TX5 随每项的新结构增加显式 schema 版本与迁移，不提前把未实现字段装成可运行能力。

每项必须带一个固定、可复现的端到端场景，另有取消、切聊天、重复、容量满和重载判据。默认开关遵循既有机制约定，关闭不产生相应写入；新增持久容器、导出、注入源、配置消费、拒收码与巡视都纳入现有登记和门禁。范围、备选和统一验收见 [本代提案](../.agents/notes/proposed/architecture/2026-10-05-worldaxis-tp-tx-plans.md)。
